publish

Spec 081: what a Trust Center publishes next to its page, and what a public one leaves out.

ShownPublicGated
the company, the period, the signer, when it was signedyesyes
each framework requirement's status, and its SCF controlsyesyes
each control's status, its counts of checks by result, stale countsyesyes
each control's evidence age (newest, oldest observation)yesyes
the SHA-256 of each full-bundle item behind a control, its kind and timeyesyes
subjects (hostnames, accounts, the repository), check titles, what each check foundnoyes
item names (paths, commit ids), people's names and emails in commitsnoyes
the evidence itself (the full bundle)no: a summary bundle, or on requestyes

A public build publishes a summary bundle it derives: the same format as spec 072's (stolos-evidence/1, each item by its SHA-256, hash-chained), signed by the same fleet signer as the full bundle through a signing callback (Signer, spec 072's sshSigner). Its items are one JSON document per control and one index, holding only what the public column above says, each bound to the full bundle by its manifest head and its own items' SHA-256. A gated build publishes the full bundle as it is.

Source: src/archon/trust/publish.ts
