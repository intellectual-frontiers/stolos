unifi

Spec 109-integrations-api FR-009 to FR-018: UniFi Network, the first router of the integration layer. It reads the UniFi Network application's local integration API, in the version Ubiquiti publishes on its official CDN (10.3.58: its OpenAPI 3.1 document is pinned in vendor/unifi-network/, and the types of unifi-api.auto.ts are generated from it), over a controller's own address with the key the owner creates in the Network application (Settings, Control Plane, Integrations): X-API-KEY.

  • Only what the document offers. unifiGet and unifiPaged take a path of the document's GET operations (UnifiGet), so a path the document does not have, such as a DHCP leases endpoint, does not compile. What the document does not offer (dhcp-leases, port-forwards, routes) is notOffered, with its reason, and a gap in every observation.
  • Read-only. GET only; the connector's transport refuses every other method.
  • A certificate that is verified. Pinned by fingerprint, or by an explicit CA, or by the system's roots (unifi-tls.ts); never switched off. stolos connect unifi shows the person a certificate no public authority signed, and pins it only on a yes.

Source: src/archon/connect/unifi.ts
