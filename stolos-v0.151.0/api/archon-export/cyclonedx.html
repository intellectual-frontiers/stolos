cyclonedx

Spec 092: the fleet's compliance as a CycloneDX 1.6 attestation (CDXA): the standard, what the fleet claims for each requirement, the evidence behind each claim, and how far each claim conforms.

  • definitions.standards: the Secure Controls Framework, by release, whose requirements are the SCF controls Stolos gives evidence for (scf.ts), with SCF's description when the catalog is on this PC.
  • declarations.claims: one per control. The target is the fleet; the predicate is what Stolos looks at, in plain words (scf.ts how).
  • declarations.evidence: each check's result (named by its OSCAL observation's UUID, urn:uuid:..., the same as in the assessment results made at the same time) and, when a spec 072 evidence bundle is given, each item in it by its path there (objects/<sha256>). Each claim names the bundle by its SHA-256.
  • declarations.attestations: the fleet (a self-assessor) maps each requirement to its claim, with a conformance score: the share of the control's checks that pass (0 without evidence), and why.
  • declarations.affirmation: the fleet signer who signed the bundle (or the one given), named, with no signature here: the signature is the bundle's (spec 072), which the signatory's external reference points to.

The same input exports the same document: the serial number is a UUIDv5 of the fleet and the time.

Source: src/archon/export/cyclonedx.ts
