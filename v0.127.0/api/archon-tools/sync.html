sync

archon tools sync (spec 008, Articles V and XII).

upstream-binary: latest GitHub release -> verify the asset's published SHA-256 digest -> install under /opt/tools/<id>/<version> -> smoke test -> atomically switch /usr/local/bin/<bin> -> keep the previous version. apt: installed by apt; reported against the candidate in Ubuntu's archive. Nothing is ever built from source on a host: binaries only. self-updating: install for persona holders, then record versions only.

Source: src/archon/tools/sync.ts

Releaseinterface
interface Release

A tool's latest stable GitHub release, as latestRelease reads it.

MemberTypeWhat it is
tagstringThe release's git tag, as published (for example "v2.1.0").
versionstringThe version: the tag without the tool's tag prefix.
assets{ name: string; url: string; digest?: string | undefined; }[]The release's downloadable files, each with its published digest when GitHub has one.
ToolStatusinterface
interface ToolStatus

One tool's row in a archon tools sync run: what is installed, what is latest, what was done.

MemberTypeWhat it is
idstringThe tool's id.
source"apt" | "self-updating" | "snap" | "upstream-binary"Where it comes from: upstream-binary, apt or self-updating.
installed?stringThe installed version (for self-updating tools, one entry per user, joined by ; ).
latest?stringThe latest version: the GitHub release, the apt candidate, or "self-updating".
debian?stringThe candidate version in Ubuntu's archive, for apt tools (the report's "Trixie" column).
actionstringWhat the run did or would do ("current", "upgraded a -> b", "FAILED: ...", and so on).
okbooleanFalse when the tool failed to sync.

versionFromfunction
function versionFrom(output: string): string | undefined

Extract the version number from --version output.

githubTokenfunction
function githubToken(): Promise<string | undefined>

A GitHub token for release lookups: GITHUB_TOKEN, else the gh login of the checkout's owner (ops, spec 016). Unauthenticated, the API allows 60 calls an hour per IP address, which one bootstrap behind a shared NAT can exhaust (every tool then fails with "GitHub API 403").

latestReleasefunction
function latestRelease(repo: string, tagPrefix?: string): Promise<Release>

The latest stable release of a GitHub repository (owner/name), read from the releases API (or the mirror in ARCHON_GITHUB_API). tagPrefix is cut from the tag to give the version. Throws on an HTTP error or a pre-release.

pinnedReleasefunction
function pinnedRelease(pin: { version: string; asset: () => Promise<{ name: string; url: string; sha256: string; }>; }): Promise<Release>

A pinned release (spec 096): the one asset for this machine, with its pinned SHA-256.

installUpstreamfunction
function installUpstream(t: ToolDef, rel: Release, arch: "amd64"): Promise<void>

Spec 010 FR-001: download a release's asset, refused unless it matches the release's published SHA-256; unpack it into /opt/tools/<tool>/<version>, link its commands into /usr/local/bin, smoke-test it, and roll the links back to the previous version when the test fails.

syncToolsfunction
function syncTools(host: HostDef, opts: { reportOnly: boolean; }): Promise<{ rows: ToolStatus[]; report: string; failed: boolean; }>

archon tools sync: bring every tool in the host's plan up to date (or, with reportOnly, only report what would change). As root, it also writes the week's Markdown report under the state directory's reports/ and logs a summary to the journal. Must run as root unless reportOnly.

listToolsfunction
function listTools(host: HostDef, opts: { latest: boolean; }): Promise<{ id: string; source: string; installed?: string | undefined; latest?: string | undefined; }[]>

Each tool in the host's plan with its installed version and, when latest is set, the latest GitHub release (upstream tools only; a lookup error is shown in place of the version).

function toolSummary(rows: ToolStatus[]): string

"fish 4.9.3 · gh 2.103.3 (new) · ..." for the Tools phase result.
