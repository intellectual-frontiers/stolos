populations

Spec 083: populations. A control is tested on a population: every unit the control should have acted on in the period (every leaver, every change, every active account). Each population here is a typed query over one evidence bundle's items (spec 072), never over this PC's live state, so an auditor who has the bundle computes the same population, and the same hash, offline.

PopulationOne unit isFrom the bundle's items
changea commit to the fleet repository in the periodeach commit item
leaversa person whose employment ended in the periodthe HR system's observations, and each system's
mfaan active account (not a service account)each system's last observation in the period
devicesa device or adopted machinethe last observations, and adopted machines'
repositoriesa code repositorythe code hosts' last observations
access-reviewsa manager's quarterly access revieweach people item, with its approving commit
verifya managed server's verify or install resulteach verify item

A unit's items are the SHA-256s of the bundle items that are its evidence. The population's hash covers its id, the bundle's manifest head, and each unit's id and items, in order of id:

Source: src/archon/audit/populations.ts
