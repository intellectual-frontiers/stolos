HTTPS on every server

service

Spec 100: remote access to the Stolos Console, on the controller. One object holds what the HTTPS side needs between requests:

  • registration (FR-004): the options for a new passkey (the challenge kept here), its verification, and the pending code;
  • the signed tip (FR-006): git fetch, then checkTip against the signers this checkout trusts, never an older tip than the last one honoured, then access.ts read from that tip;
  • sign-in (FR-007): the options, the verification against access.ts's public keys, the counter and the last sign-in in local state, five failures a minute pausing an address;
  • privileges (FR-009): who may sign here (their key is on this controller);
  • audit (FR-011): every event to the activity record (kind access) and, at once, to the fleet's mailbox (best effort), with a daily digest of remote sign-ins and commands.

Source: src/archon/access/service.ts
