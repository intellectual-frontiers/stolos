core

Spec 078: how a control's answer becomes a result. Each runner here is pure: it is given the rows (or the observation) and returns PolicyResults, so the built-in policies (adopted machines, devices, the estate graph) and a fleet's own packs give results the same way, and accepted risks apply to both alike.

Source: src/archon/controls/core.ts

acceptRisksfunction
function acceptRisks<R extends PolicyResult>(accepted: readonly Acceptance[], rs: R[], now?: number): R[]

Failing results the owner accepted (until a date) become "accepted", with who, why, and until when; after the date they fail again, saying so. A pass or an unknown is never changed.

SubjectResulttype
type SubjectResult = PolicyResult & { subjects: string[] };

A result with the estate node uids it is about (estate controls).

toResultfunction
function toResult(c: { id: string; title: string; scf: readonly string[]; }, v: Verdict, fix: string | undefined): PolicyResult

A verdict as a PolicyResult, in the built-ins' key order (id, title, scf, status, detail, fix).

runObservationfunction
function runObservation<K extends ObservationKind>(c: ObservationControl<K>, input: ObservationInputs[K]): PolicyResult | undefined

One observation control on one subject; undefined when it does not apply.

runObservationsfunction
function runObservations<K extends ObservationKind>(cs: readonly ObservationControl<K>[], input: ObservationInputs[K]): PolicyResult[]

Every observation control of a list on one subject, in order.

estateRowsfunction
function estateRows<Q extends EstateQuery>(q: Q, query: (sql: string) => Row[]): EstateRows<Q>

The rows an estate control's query (one SELECT, or several by name) answers, from query.

runEstatefunction
function runEstate<Q extends EstateQuery>(c: EstateControl<Q>, query: (sql: string) => Row[], now: Date): SubjectResult | undefined

One estate control, given a read-only query function; undefined when it does not apply.
