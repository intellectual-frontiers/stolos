telemetry

The boot server's own telemetry (spec 023, on IFC TypeScript since spec 096). The boot server's signals are IFC TypeScript's (runtime/otel), in-process: started once with initBootTelemetry, they are kept in a journal in the boot cache (OTLP JSON lines, OpenTelemetry's file format, rotated by size: 256 MB at most, and kept 30 days) and sent over OTLP/HTTP to otel-tui while it runs on this PC (localhost:4318, the pipeline's default; silent where nothing listens). Nothing else leaves the PC. There is no restart to turn telemetry on.

Spec 049: the boot server is also the fleet's default collector. Servers that find no other (fleet.telemetry, or otel.localdomain) send their telemetry to http://<boot PC>:<http port>/otlp, which IFC TypeScript's OTLP receiver decodes; it is kept a week (ephemeral) in daily files.

Each install is one trace, an archon.boot.install span (its host in host.name), with an archon.boot.step span per step (its name in archon.boot.step).

Source: src/archon-boot/telemetry.ts

initBootTelemetryfunction
function initBootTelemetry(dir?: string): void

Start the boot server's own telemetry, in this process: on the pipeline already installed, or a new one (service archon-boot), with the journal in dir. Safe to call twice; the first call wins.

stopBootTelemetryfunction
function stopBootTelemetry(): Promise<void>

Flush the boot server's telemetry and shut its pipeline down (the boot server stops).

prunefunction
function prune(dir: string, keepDays: number, keepBytes: number): Promise<void>

Remove a folder's daily files (otlp-<date>.jsonl), oldest first, while any is older than keepDays or they hold more than keepBytes in all; the newest is always kept.

Where the fleet's servers' telemetry lands when the boot PC is their collector (spec 049).

FLEET_KEEPconst
const FLEET_KEEP: { days: number; bytes: number; }

The fleet collector is ephemeral: a week, 512 MB at most.

FLEET_OTLP_PATHconst
const FLEET_OTLP_PATH: "/otlp"

Under the boot server's HTTP port, which the servers already reach (spec 049).

otlpHandlerfunction
function otlpHandler(dir: string, keep: { days: number; bytes: number; }, prefix?: string): (req: Request) => Promise<Response>

A handler for OTLP/HTTP with JSON bodies (gzip or not), on IFC TypeScript's OTLP receiver: each batch becomes one OTLP JSON line of a daily file in dir, pruned to keep; when otel-tui runs on this PC, the batch is also handed to it. Paths are /v1/traces, /v1/metrics, /v1/logs after prefix; protobuf is refused (415).

recordEventsfunction
function recordEvents(events: ArchonEvent[], resource: Record<string, string>, dir?: string): Promise<void>

Spec 049: record events as OpenTelemetry log records, the source of what the window and boot.log show: one OTLP logs request per batch of events, in a daily file of TELEMETRY_DIR (and to otel-tui when it runs).
