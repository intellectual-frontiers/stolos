connections

043-pg-connections: what this account's libpq would use, and how to reach an instance. Read-only; nothing on the host changes.

archon pg connections every entry of the password file and every section of the service files, matched as libpq matches them archon pg show NAME how to reach an instance, as conninfo, URL, PG* environment, or a service section

A password is never printed, logged, or returned: the password field is dropped the moment a password-file line is split, and a password key in a service file is dropped as it is read. Only whether one is there is kept.

Source: src/archon/pg/connections.ts

PgpassEntryinterface
interface PgpassEntry

One password-file line, without its password.

MemberTypeWhat it is
linenumber1-based line number in the file.
hoststringThe host field, as written ("*" matches any); empty when malformed.
portstringThe port field, as written ("*" matches any); empty when malformed.
databasestringThe database field, as written ("*" matches any); empty when malformed.
userstringThe user field, as written ("*" matches any); empty when malformed.
hasPasswordbooleanWhether the line has a fifth field (libpq's password); never the field itself.
malformed?stringWhy libpq cannot use the line (it has fewer than five fields).
splitPgpassLinefunction
function splitPgpassLine(line: string): { fields: string[]; hasPassword: boolean; }

Split one line into libpq's fields (backslash escapes : and \). The fifth field, the password, is consumed and discarded here: only its presence leaves this function.

parsePgpassfunction
function parsePgpass(text: string): PgpassEntry[]

Parse a password file into its entries, skipping blank lines and comments. A malformed line keeps only its line number and why: none of its fields.

ConnectionsReportinterface
interface ConnectionsReport

What archon pg connections reports: the password file, the service files, and how they match.

MemberTypeWhat it is
passwordFile{ path: string; exists: boolean; mode: string | null; usable: boolean; problem: string | null; }The password file: where it is, its mode, and whether libpq would use it.
serviceFiles{ path: string; source: "system" | "user"; exists: boolean; }[]The service files libpq reads, and whether each exists.
entries{ line: number; host: string; port: string; database: string; user: string; services: string[]; usable: boolean; problems: string[]; }[]Each password-file entry, the services it serves, and its problems.
services{ name: string; file: string; source: "system" | "user"; host: string; port: string; database: string; user: string; sslmode: string | null; passwordEntry: number | null; problems: string[]; }[]Each service section in effect (a user's section hides a system one of the same name).

interface ConnectionsInput

What connectionsReport reads: the account and its files, already loaded (text absent when missing).

MemberTypeWhat it is

serviceFiles{ path: string; source: "system" | "user"; text?: string | undefined; }[]The user's and the system's service files, in the order libpq reads them.
connectionsReportfunction

Match the password file against the service files as libpq would, and say what is wrong: a file libpq ignores, a password in a service file, network TLS that is not verify-full, an entry no service uses. Pure: no I/O.

Targetinterface
interface Target

Where an instance is, and as whom. Never a password.

MemberTypeWhat it is
namestringThe instance's, cluster's, or service's name.
hoststringThe socket directory, or a host name for a network connection.
portnumberThe port it listens on.
databasestringThe database to connect to (the role's default).
userstringThe role to connect as.
networkbooleanOver a network: verify-full against the system's roots.
address?stringThe server's IP address, for a client without DNS for the name (libpq's hostaddr).
kind?"human" | "service"A person (their Linux password) or a service account (its generated password).
server?stringThe server it runs on (for the PAM reminder).
pamReminderfunction
function pamReminder(t: Pick<Target, "kind" | "name" | "server" | "user">): string | undefined

The reminder that goes with any external connection for a person: PostgreSQL learns a Linux password only when it is typed on the server (PAM, spec 039).
