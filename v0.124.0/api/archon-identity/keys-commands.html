keys-commands

Spec 057: stolos keys, every step of your signing keys in one place, and idempotent: each command looks at what is already there, does only what is missing, and can be run again at any time (after a failure, it continues).

  • keys: the checks (nothing changes).
  • keys setup: tools, the daily key, Git's settings, signers.ts, the recovery key, the pre-push check, and a test signature.
  • keys check-recovery --key <file>: proves the recovery key still works.
  • keys rotate: a new daily key, approved by the old one.
  • keys lost --recovery <file>: a new daily key, approved by the recovery key.
  • keys check-push: the pre-push check (Git runs it).

Passphrases are typed into OpenSSH and Git themselves: archon never sees, stores, or passes one, and never loads a key into an ssh-agent. None of these commands is offered over MCP.

Source: src/archon/identity/keys-commands.ts

The exact commands that approve a new PC's daily key: run where a listed key signs (on WSL, Windows PowerShell in the fleet folder), then pull here.

keysSetupfunction
function keysSetup(o?: { test?: boolean | undefined; }): Promise<number>

stolos keys setup: everything, idempotent.

repairKeysfunction
function repairKeys(): Promise<string[]>

The parts of keys setup that need no passphrase and make no key (spec 058: run by archon update after every pull): Git's allowed signers from the current signers.ts, and the pre-push check. Returns what it changed.

keysCheckRecoveryfunction
function keysCheckRecovery(given?: string | undefined): Promise<number>

stolos keys check-recovery --key <file>: prove the recovery key works; changes nothing else.

keysRotatefunction
function keysRotate(): Promise<number>

stolos keys rotate: a new daily key, approved by the current one; resumes a rotation in progress.

keysLostfunction
function keysLost(given?: string | undefined, stolen?: boolean): Promise<number>

stolos keys lost --recovery <file>: replace a lost or stolen daily key, approved by the recovery key.

keysRotateRecoveryfunction
function keysRotateRecovery(o: { old?: string | undefined; oldLost?: boolean | undefined; }): Promise<number>

stolos keys rotate-recovery --recovery <old file> (or --old-lost): a new recovery key in place of the old one (same signer name). The change is approved by the OLD recovery key, proving you still hold it; only when it is lost does the daily key approve (a stolen daily key could do the same, so that path says so). The new key is tested before anything changes; running it again continues an interrupted change, or does nothing.

keysCheckPushfunction
function keysCheckPush(input?: string | undefined): Promise<number>

stolos keys check-push (Git's pre-push hook): each pushed tip of the fleet's branch must be signed by a key the fleet trusts as of what the remote has now, exactly as servers will check it. Refs to push come on standard input ("<local ref> <local sha> <remote ref> <remote sha>").

keyChecksNowfunction
function keyChecksNow(): Promise<KeyCheck[]>

The checks for other commands (boot doctor, where am I): the facts are gathered once.

signingBlockersfunction
function signingBlockers(repo?: string): Promise<KeyCheck[]>

What stops a signed commit (git commit -S) in repo right now, as checks: OpenSSH, Git set to sign with an SSH key that exists, and Git's identity. Empty: a commit can be made and signed. A fresh clone fails here until vault restore or keys setup ran in it.
