Workstation (Ubuntu on WSL)

020Implemented

020-workstation

Input

The owner's Windows PC runs Ubuntu on WSL; it should get the same tools, dotfiles, prompt as the hosts, managed by Archon, without anything that belongs to a server. The agent is the workstation's own MCP client, which the operator chooses and sets up; Archon renders only .mcp.json for it (spec 030).

#User Scenarios & Testing (mandatory)

#User Story 1: Set up WSL Ubuntu as a workstation (Priority: P1)

Acceptance Scenarios:

  1. Given Ubuntu 26.04 on WSL with systemd, and the repository cloned to /srv/archon by the owner, When the owner runs bun run stolos workstation add, Then fleets/<fleet>/hosts/<name>/host.ts is written (kind: "workstation", user: <owner>), and through sudo the workstation gets the tools at their newest releases, the dotfiles, the archon command, and Ubuntu's daily updates; a new terminal opens in fish with the Archon prompt.
  2. Given the wrong Ubuntu release, no systemd, or a checkout elsewhere, Then it stops before changing anything, with the fix for each.
  3. Given a workstation in the model, Then the boot server never lists, arms, or installs it.

#Requirements (mandatory)

FR-001

HostDef.kind is "server" (default) or "workstation"; a workstation names the existing account it sets up (user, default the fleet admin's name) and has no mac, disk, guests, backup, or extra users (validated).

FR-002

workstation() is the workstation's capability set: a base (Archon's directories, /etc/archon/host, git, curl, unzip, software-properties-common, a systemd check), accounts (Archon's groups and sudo rule; no ops), updates (spec 009), tools (spec 010), shell (spec 011), and the CLI (spec 012).

FR-003

The workstation has one account, its user, with the operator persona (fish, oh-my-posh, tmux, developer tools, archon completions). It is never created: WSL created it.

FR-004review

archon workstation add [<name>] [--user <u>] [--force] runs as the user from /srv/archon, checks the Ubuntu release against the fleet's, that systemd runs (fix: /etc/wsl.conf [boot] systemd=true, wsl --shutdown), and the checkout location, writes the host file, installs the engine bun.lock holds (bun install --frozen-lockfile), then runs archon update --no-pull --host <name> through sudo with the same runtime (Bun, or Node 26). Later changes come with sudo archon update.

Reviewed: The VM end-to-end run (.github/workflows/e2e.yml, step "Install a VM end to end", tests/e2e/lib.sh workstation_stage): on an Ubuntu cloud-image VM with the repository cloned to /srv/archon, `stolos workstation add` must succeed (release, systemd and checkout checks, the host file, bun install --frozen-lockfile, archon update through sudo), then `archon verify` and a fleet query from the workstation must pass, or the run fails.

FR-005

The boot machine ignores workstations (loadServers).

#Overrides of Ubuntu defaults

None beyond those of specs 009 to 012, which apply unchanged.

#Success Criteria (mandatory)

SC-001success criterion

After workstation add, archon verify passes on the workstation, and a new terminal is fish with the Archon prompt.
