bun-pin

The pinned runtimes (spec 096-bun-runtime FR-007): the one Bun every host, the boot server and the operator's PC run the engine with, and the Node 26 that is the backup where Bun cannot run. Each is a version and the SHA-256 of its official release archive for each platform; a download is unpacked only where its SHA-256 is the one written here. Raising a pin is a change to this file, reviewed like any other.

  • Bun 1.4.4, the version commons pins (pmid:pin-bun in commons' ontology/supply-chain/packaging/pins.ttl). Its archives are https://github.com/oven-sh/bun/releases/download/bun-v<version>/bun-<target>.zip, each holding bun-<target>/bun (bun.exe on Windows). The checksums of linux-x64, linux-aarch64, darwin-x64, darwin-aarch64 and windows-x64 are commons' own (pmid:sum-bun-*); the baseline builds (for a processor without AVX2) and windows-aarch64 are from the release's SHASUMS256.txt.
  • Node 26.13.1, from https://nodejs.org/dist/v<version>/SHASUMS256.txt: node-v<version>-<target>.tar.gz (.zip on Windows), holding node-v<version>-<target>/.

The module imports nothing at run time, so a CI step can read it with Node before anything is installed (node -e 'import("./src/archon/core/bun-pin.ts")'). The bootstraps (bin/bootstrap.sh, bin/bootstrap.windows.ps1) carry the same values, and the engine's tests keep them equal.

Source: src/archon/core/bun-pin.ts

  | "windows-x64"
  | "windows-x64-baseline"
