transport

How mail leaves (spec 025, spec 027): Cloudflare Email Service's authenticated SMTP submission, smtp.mx.cloudflare.net:465 with implicit TLS, user "api_token", the password a Cloudflare API token with Email Sending: Edit. Cloudflare signs with DKIM for the onboarded sending domain.

archon's own messages go straight there with curl (Cloudflare's own example client), so archon keeps its queue, dedupe, and outage summary. Everything else on a server (apps, cron, unattended-upgrades) goes through Postfix, which relays to the same place with the same token (capabilities/mail.ts). curl reads its configuration, token included, on stdin (-K -): never in argv, never in a process listing.

Source: src/archon/notify/transport.ts

DEFAULT_RELAYconst
const DEFAULT_RELAY: "smtp.mx.cloudflare.net:465"

The SMTP relay, host:port, when the fleet names none (fleet.mail.relay): Cloudflare, implicit TLS.

RELAY_USERconst
const RELAY_USER: "api_token"

Cloudflare's SMTP user name: the literal string api_token.

senderAddressfunction
function senderAddress(mail: { domain: string; tag?: string | undefined; }, host: string, user: string): string

A machine's sender (spec 027): <user>+<host>[.<tag>]@<domain>, one onboarded domain for the whole fleet, the machine in the subaddress (RFC 5233).

hostLabelconst
const hostLabel: (mail: { tag?: string | undefined; }, host: string) => string

The detail part of the subaddress: alpha.lab.

Credentialinterface
interface Credential

The credential: a Cloudflare API token with the Email Sending: Edit permission.

MemberTypeWhat it is
tokenstringThe API token (the SMTP password). A secret: never logged or sent.
createdstringWhen it was made (ISO 8601); empty when read back from sasl_passwd.
user?stringThe SMTP user name, for a relay other than Cloudflare's (spec 092: a tenant's own send-only account). Default: RELAY_USER.
secretsOffunction
function secretsOf(c: Credential | undefined): string[]

Every secret string a credential holds (for redaction).

relayPartsfunction
function relayParts(relay?: string): { host: string; port: number; }

Split host:port; the port is 465 when missing or not a number.

SmtpTlstype
type SmtpTls = "implicit" | "starttls";

How TLS starts: at once (implicit, port 465), or by STARTTLS after EHLO (submission, port 587).

tlsForconst
const tlsFor: (port: number) => SmtpTls

The TLS mode for a port when none is given: STARTTLS on 587 and 25, implicit TLS otherwise.

SmtpOptionsinterface
interface SmtpOptions

One SMTP session's options (curl's configuration is built from these).

MemberTypeWhat it is
relay?stringhost:port of the relay (default DEFAULT_RELAY).
ipv4booleanReach it over IPv4 only.
from?stringThe envelope sender.
to?stringThe envelope recipient.
file?stringThe message file to upload (none: log in and NOOP).
tls?SmtpTlsHow TLS starts (default by port, tlsFor). Either way TLS is required (ssl-reqd): curl refuses to log in or send over a connection without it.
cacert?stringA CA bundle to trust instead of the system's (tests with their own certificate).
smtpConfigfunction
function smtpConfig(c: Credential, o: SmtpOptions): string

curl's configuration for one SMTP session with the relay (token included: stdin only).

EMAILconst
const EMAIL: RegExp

A plausible email address (one @, a dot in the domain, no spaces or angle brackets).

smtpErrorfunction
function smtpError(exit: number, stderr: string, ctx?: { from?: string | undefined; to?: string | undefined; relay?: string | undefined; }): string

What a failed SMTP session means, in plain words: the step that failed (log in, the sender, the recipient, the message), what was tried there, the server's reply code, and the likely fix. curl reports the step and the code ("RCPT failed: 500"); the token is never part of it.

sendSmtpfunction
function sendSmtp(c: Credential, o: Omit<SmtpOptions, "file"> & { from: string; to: string; }, mime: string): Promise<string>

Send one RFC 5322 message (CRLF line ends) through the relay.

probeSmtpfunction
function probeSmtp(c: Credential, o: Omit<SmtpOptions, "file" | "from" | "to">): Promise<void>

Log in to the relay and leave, sending nothing (archon doctor, mail-setup).

SASL_PASSWDconst
const SASL_PASSWD: "/etc/postfix/sasl_passwd"

Postfix's SMTP client credential: one line, root only (capabilities/mail.ts).

saslPasswdfunction
function saslPasswd(c: Credential, relay?: string): string

The text of Postfix's sasl_passwd for this credential: a comment, then [host]:port api_token:<token>. It holds the token: write it root only.

parseSaslPasswdfunction
function parseSaslPasswd(text: string): Credential | undefined

The token back out of Postfix's file (archon's own sends use the same one).
