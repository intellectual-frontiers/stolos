Custom controls

#Custom controls

A company writes its own controls in TypeScript, tests them like code, and keeps them in the fleet repository beside everything else (spec 078). A control is a query plus an assertion, tagged with the Secure Controls Framework (SCF) controls it gives evidence for; its results show up in stolos compliance and the Compliance tab, as evidence from a "control pack". Stolos's own policies (adopted machines, devices, and the estate graph's cross-system checks) are written the same way, on the same SDK.

#A control

Each control has a subject:

subjectIt asksResults
estateSQL over the estate graph (stolos estate schema), read-onlyone, across systems
osqueryone osquery SELECT on each adopted machine, through its probeone per machine
observationan adopted machine's, a device's, or an account's observationone per subject

Its assert returns a verdict (pass, fail, warn, or unknown, with what was found), or undefined when it does not apply. scf lists SCF control ids, typed: a wrong id fails type checking. fix says how to make it pass.

An estate control's query may be one SELECT or several by name ({ admins: "...", known: "..." }); its assert then gets each one's rows by name.

#A pack in the fleet repository

Put each pack in its own folder: fleets/<fleet>/controls/<pack>/pack.ts exports the pack (as pack, or as its default export), and <pack>.test.ts beside it tests it. Stolos loads every pack there. A risk the owner accepts is recorded in fleets/<fleet>/controls/accepted.ts:

A failing result it names shows as accepted (not as passing) until the date. An adopted machine's own accepted list in machine.ts applies to its results too.

#Testing a control

testControl(control, fixture) runs one control over a fixture and returns its results as Stolos would show them. A fixture is rows (rows, or machines for osquery), an estate made from a few records (estate, built with fixtureEstate), or an observation (input); add accepted and now as needed.

In the fleet repository, bun test fleets/ (or node --test fleets/) runs every test; stolos controls test runs the packs' tests with the runtime Stolos runs on.

#Commands

controls list shows each pack and its controls. controls run runs them now: estate controls over the graph built from Git, observation controls over the observations in Git, and osquery controls on each adopted machine through its probe. It keeps each machine's answer on this PC, so stolos compliance and the consoles show osquery results without asking machines again. controls test runs the packs' tests. An example pack is in the engine's repository, examples/fleets/lab/controls/baseline/.
