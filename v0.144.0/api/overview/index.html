Overview

#Stolos: the fleet engine

Stolos installs, converges, and verifies a fleet of Ubuntu servers and workstations from a model written in TypeScript. Its command is archon. The engine (this repository, public) holds no fleet: each fleet lives in a fleet repository (private), under fleets/<id>/, and depends on the engine's package of a released tag.

Start with: bun run stolos in a fleet repository (where you are, and the one thing to do next), then the model's types (FleetDef and HostDef in archon/model/types.ts), then the guides: each folder's mod.ts documents it (listed in archon/core/guides.ts; offline: bun run stolos docs).

#Two repositories, one approval

A host moves only to a tip signed by a signer it trusts, descending from the one it runs. The lock makes that signature cover the engine's code too.

#How a machine becomes a host

#What a machine knows about itself

Git holds intent (the model, decisions, who each host is); each machine holds what it observed, and is asked, never pushed from.

#Four states, everywhere

Every problem has a stable code: archon explain <code>.

#Where things are

  • archon/model/: the model's types, loading, and validation.
  • archon/capabilities/: what a host gets (packages, files, units, checks).
  • archon/install/: host add, the first boot, bootstrap, recognition.
  • archon-boot/: the boot server (PXE, GRUB, the blank-disk guard).
  • archon/identity/: signers and signatures.
  • archon/fleet/: upgrade, registration, decisions, scaffolding.
  • archon/state/: archon.sql, verify, query, inventory.
  • archon/telemetry/ and archon/core/telemetry.ts: OpenTelemetry.
  • archon/guide/: where am I, and the guide.
  • archon/core/: paths, the terminal UI, explain, secrets.
