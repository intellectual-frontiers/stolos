Clients: one PC, many client fleets

#Clients: one PC, many client fleets

Managed service providers and virtual CISOs look after many small companies' security. Stolos lets one person do that from one PC (spec 082) while each client stays entirely its own: its own fleet repository, its own vault (the secrets on this PC), and its own signers.

#Setting up clients

Clone each client's fleet repository wherever you keep your work, then register each checkout once:

The registry is one file of yours (clients.json in Stolos's config folder: on Windows %APPDATA%\stolos, elsewhere ~/.config/stolos): each client's id, title, the path of its checkout, and the fleet in it. It is never written into any client's repository, and it holds no secret. clients remove <id> forgets a client and deletes nothing.

Then any command works for one client:

or choose a client for every command until you choose another (--client still wins for one command; --clear goes back to the repository you are in):

Your signing key signs a client's commits and bundles only if that client's signers.ts lists it: each client adds you as a signer in its own repository (stolos signers add, a commit signed by one of its signers). One key may be on several clients' lists, or you may keep one key per client (--key on evidence export).

#What stays apart

--client <id> sets the repository, the fleet, and the client for the whole run (ARCHON_REPO, ARCHON_FLEET, ARCHON_CLIENT), and every per-user folder moves under stolos/clients/<id>/:

WhatWhere, for client <id>
the repository, the model, rendered outputthe client's checkout
state: records, evidence bundles, OSCAL, logs<data>/stolos/clients/<id>/state/<fleet>
secrets (the vault)<config>/stolos/clients/<id>/secrets/<fleet>
the key store (recovery key)<config>/stolos/clients/<id>/keys
the backup ledger<data>/stolos/vault/clients/<id>/ledger.json
a backup ZIPstolos-backup-<pc>-<id>-<time>.zip, that client's secrets only

The downloaded catalogs (public reference data) and the boot server's cache are shared. Two clients never share a checkout: clients add refuses a checkout that is another client's, or inside it, or holds it.

  • A bundle (evidence export), the OSCAL documents (compliance export), and the Trust Center (trust build) are made from one client's checkout and folders, signed by one of that client's signers; a key that is not on its list is refused.
  • clients report --out <folder> writes <folder>/<id>/ for each client (its report, its numbers, its compliance view), each read in its own scope, and refuses a folder inside any client's checkout.

#The summary

clients summary (and the console's Clients page, and /v1/clients) reads each client on its own and shows numbers and dates only:

  • controls passing, failing, partial, without evidence, and with stale evidence;
  • controls changed in the last day (--since), and how many got worse;
  • when anything was last observed;
  • open POA&M items (failing checks, open risks in the register, open vulnerabilities);
  • the date of the newest evidence bundle on this PC.

No machine, account, check, finding, or person of any client is in it. A client that cannot be read is shown as not read, with a general reason.

#The provider's console

It opens like the Stolos Console (127.0.0.1, a one-time launch link) on the Clients page: the summary, with an Open button per client. Opening a client ends your session and starts a new one for that client alone: every page, the REST API under /v1/, and every command you run there are that client's, from its checkout, its folders, and a console of its own (its own sessions and caches). The top bar names the client, with a link back to All clients. To see another client, switch again: an old session's cookie stops working, so no tab left open on one client ever shows another's pages.

The boot server's log is this PC's (installs at every client's site), so a client's Installs page in the provider's console is empty; run stolos --client <id> console for one client's console with everything.

#Modules

commandsSpec 082: the stolos clients commands (add, list, remove, use, summary, report, console) and --client <id>, which runs any command in one client's scope.
consoleSpec 082: the provider's console (stolos clients console): one Stolos Console for every client, on this PC only (127.0.0.1, a one-time launch link, as spec 066).
launchSpec 082: each client's console inside the provider's console, built once per client, in that client's scope: its facts, estate, compliance, REST API, activity record, and caches come from its own…
registrySpec 082: the provider's registry of client checkouts.
reportSpec 082: stolos clients report --out <folder>: one report per client, each in its own folder (<folder>/<client>/), each read in that client's scope, plus the cross-client summary at the top…
scopeSpec 082: running in one client's scope.
summarySpec 082: the cross-client summary.
