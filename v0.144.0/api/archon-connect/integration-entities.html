integration-entities

Spec 109-integrations-api: the typed entities an integration reads, one for each capability of each kind (a router's clients, its devices, its VLANs; a DNS provider's zones and records; an email provider's domains and routes). They are plain data with no secret and no personal field: what a control needs, and no more.

Each entity joins the estate graph (spec 085, 090) through the observation a connector writes: as a record with a label named from OCSF or D3FEND and its OCSF class (spec 089), and a network device also as a device entity, so that it is a fixed asset beside the fleet's machines. entityParts is that one mapping, a switch over every capability of every kind that the compiler checks is complete.

Source: src/archon/connect/integration-entities.ts

Kindtype
type Kind = ApiKind;

The kinds of API an integration may be: the ontology's stolos:ApiKind.

CapabilityOftype
type CapabilityOf<K extends Kind> = ApiCapability extends infer X
  ? X extends `${K}-${infer C}`
    ? C
    : never
  : never;

The capabilities of a kind: the ontology's stolos:ApiCapability codes that start with <kind>-, without it. One list of words, so a capability added there is a capability of its kind here.

Resultsinterface
interface Results

What each capability of each kind reads: the typed entities. The compiler checks that this is exactly the ontology's capabilities.

MemberTypeWhat it is
router{ "dhcp-leases": Lease[]; clients: Client[]; devices: NetworkDevice[]; "networks-and-vlans": Vlan[]; ports: SwitchPort[]; "port-forwards": PortForward[]; "firewall-rules": FirewallRule[]; wifi: WifiNetwork[]; routes: Route[]; health: RouterHealth[]; }A router's.
dns{ zones: DnsZone[]; records: DnsRecord[]; }A DNS provider's.
email{ domains: EmailDomain[]; sending: EmailSender[]; routing: EmailRoute[]; }An email provider's.
ResultOftype
type ResultOf<K extends Kind, C extends CapabilityOf<K>> = Results[K] extends infer R
  ? C extends keyof R
    ? R[C]
    : never
  : never;

The result of one capability of a kind: its entity list.

Completetype
type Complete<K extends Kind, R> = Same<keyof R, CapabilityOf<K>> extends true ? R : never;

R where it has exactly the capabilities of kind K, and never otherwise: a result type that lacks a capability of its kind, or has one the kind does not, is a compile error where it is used (Results is checked below).

RESULTS_ARE_COMPLETEconst
const RESULTS_ARE_COMPLETE: { dns: true; email: true; router: true; }

The compile-time check that every kind of Results has exactly its capabilities (assigning false to true fails).

Readingtype
type Reading = {
  [K in Kind]: {
    [C in CapabilityOf<K>]: {
      readonly kind: K;
      readonly capability: C;
      readonly items: ResultOf<K, C>;
    };
  }[CapabilityOf<K>];
}[Kind];

One capability of one integration, read: the kind and capability as words, and the entities as their type says.

Partsinterface
interface Parts

What the entities of a reading become in an observation.

MemberTypeWhat it is
recordsObservedRecord[]Nodes of the estate graph.
assetsAsset[]How estate assets lists them.
devicesDevice[]Devices that join the fleet's machines as fixed assets.
entityPartsfunction
function entityParts(r: Reading): Parts

One reading's entities as the parts of an observation: records (with their labels), assets and devices. The switch is over the kinds and capabilities of the ontology and items is typed by them, so a capability added to stolos:ApiCapability without a mapping here does not compile; the capabilities that no integration has implemented yet, or that are posture and not nodes (dhcp-leases, port-forwards, routes, health, sending), map to nothing (tasks.md, L003).

dmarcPolicyfunction
function dmarcPolicy(value: string): string | undefined

The policy (p=) of a DMARC record (RFC 7489 section 6.3), lower case, when it names one.
