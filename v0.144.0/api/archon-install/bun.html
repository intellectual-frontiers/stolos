bun

The pinned Bun (spec 096-bun-runtime FR-007): the runtime every host, the boot server and the operator's PC run the engine with, and how a fleet checkout gets its engine.

  • The pin: one Bun version, and the SHA-256 of its release archive for each platform, kept in the engine's core/bun-pin.ts. The first boot (render/autoinstall.ts, also run by stolos host bootstrap) downloads the archive for its machine, checks its SHA-256 before unpacking it, and links /usr/local/bin/bun. Raising the pin is a change to that file, reviewed like any other.
  • The engine in a checkout: a fleet repository depends on the engine by Git at a tag (package.json: github:intellectual-frontiers/stolos#v<version>), and bun.lock pins the tag's commit and its integrity. bun install --frozen-lockfile installs exactly that, or stops (E046-LOCK-INTEGRITY): the lock is the control.
  • The launcher (/usr/local/bin/archon, capabilities/cli.ts) runs the checkout's archon.ts with Bun, and with Node 26 where Bun is not installed. The engine's modules are TypeScript under node_modules, whose types Node 26 does not strip, so Node runs them with commons' hook first (NODE_HOOK; the launcher names its file, nodeHookFile, since Node resolves --import from the working folder).

Source: src/archon/install/bun.ts

The command every host runs Bun by.

bunInstallShellfunction
function bunInstallShell(): string

A POSIX shell fragment that installs the pinned Bun on Linux (x86-64 or ARM64) unless that version is already there: the archive for this machine (the baseline build where the CPU has no AVX2), its SHA-256 checked before it is unpacked, then /usr/local/bin/bun. It needs curl and unzip, and fails (with set -e) on any mismatch.

bunAssetHerefunction
function bunAssetHere(): Promise<{ name: string; url: string; sha256: string; }>

The pinned Bun's archive for this Linux machine, as archon tools sync installs it (spec 010): ARM64, or x86-64 (the baseline build where the processor has no AVX2), with its pinned SHA-256.

bunExecutablefunction
function bunExecutable(): string

The Bun to run: this process's own when it is Bun, else bun on the PATH, else the host's.

NODE_HOOKconst
const NODE_HOOK: "@intellectual-frontiers/commons/ts/node"

Commons' Node hook (commons 0005-typescript-runtime FR-070): Node 26 strips no types under node_modules, so a fleet's entry file runs on Node as node --import @intellectual-frontiers/commons/ts/node archon.ts (spec 096 FR-007).

nodeHookFilefunction
function nodeHookFile(repo: string): string

The file of commons' Node hook in a fleet checkout, for a command that runs from another folder: Node resolves --import from the working folder, and the package's ./ts/node is this file.

runtimeCommandfunction
function runtimeCommand(): string[]

This process's runtime, as a command that runs another TypeScript file the same way (the file and its arguments follow): Bun as it is, Node with commons' hook (spec 096 FR-007), since a child of Node does not inherit the hook and Node strips no types under node_modules.

engineCommandfunction
function engineCommand(): string[]

The command that runs a fleet checkout's stolos.ts or archon.ts (the file and its arguments follow): Bun, or Node 26 with commons' hook where Bun is not installed (spec 096 FR-007). The hook is resolved from this engine, as an absolute URL, so the command runs from any folder.
