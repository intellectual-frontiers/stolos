reconcile

archon reconcile (Article IX): approval means origin/main. Fetch, fast- forward a clean checkout, then apply only when HEAD equals origin/main. Runs a fresh archon apply process so the newly pulled code is used.

Source: src/archon/reconcile/reconcile.ts

SyncResultinterface
interface SyncResult

What syncing the checkout with origin/main found or did.

MemberTypeWhat it is
currentbooleanfetched, and HEAD now equals origin/main
pulledstring[]commits fast-forwarded in this run (subject lines)
incomingstring[]commits on origin/main not yet applied locally (when check or blocked)
headstringThe commit it runs.
remotestringorigin/main's commit.
blocked?stringwhy HEAD could not reach origin/main, if it could not

interface SyncStatus

What the last pull did, for the PC (archon state, spec 066): when, the commits, and why not.

MemberTypeWhat it is
atstringWhen it ran (ISO).
headstringHEAD after it.
remotestringorigin's commit.
currentbooleanWhether HEAD is origin's commit.
blocked?stringWhy HEAD could not reach origin's commit (an unsigned commit, a failed fetch, ...).

syncCheckoutfunction
function syncCheckout(opts?: { check?: boolean | undefined; }): Promise<SyncResult>

Fetch origin/main as the checkout's owner (who holds the host's deploy key, spec 006) and fast-forward when the working tree is clean. With check, only fetch. As root, the outcome is recorded for the PC (SYNC_STATUS).
