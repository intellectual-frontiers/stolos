pair-store

Spec 103-three-ports: where a pairing's state lives. A pairing (spec 098) has one record: the code, the fleet, when it expires, the wrong tries so far, the machine that said hello, the check-in waiting for the person, and the person's decision. stolos pair (the terminal, where the person approves) and every server that answers the machine (the boot server, the console, or the pair-only server stolos pair runs itself) are different processes, so the record is a store they share:

  • MemoryPairStore: one process (the tests, and a session with no other process);
  • FilePairStore: a short-lived file in the secrets folder, owner only and ephemeral (never backed up), the same pattern as an armed install: the command writes, the servers read per request, and there is no new port. Every change is made under a lock file (<file>-lock, taken with O_EXCL by commons' lock), read fresh inside it, and written atomically (a temporary file renamed over the record), so two processes cannot lose each other's tries.

Source: src/archon/adopt/pair-store.ts

interface PairStore

Where a pairing's record is kept: read it, change it atomically, replace it, remove it.

MemberTypeWhat it is
read() => Promise<PairRecord | undefined>The record, or undefined where no pairing is waiting.
