archon/model/types

The Archon model (spec 002): a fleet with one shared identity and one file per host. Capabilities contribute packages, files, units, and the rest to a host's plan. TypeScript types plus validate.ts are the whole validation story (Article 10); RDF is only an export.

Source: src/archon/model/types.ts

FleetDefinterface
interface FleetDef

The fleet: one identity shared by every host (spec 003), in fleets/<id>/fleet.ts of a fleet repository. stolos fleet init <id> writes the first one from your GitHub account; edit it freely after, then stolos build.

MemberTypeWhat it is
idstringThe fleet's id: its folder, fleets/<id>/, and a DNS label (lowercase, digits, hyphens).
titlestringIts name, for people.
repository{ slug: string; url: string; branch?: string | undefined; }The GitHub repository hosts converge to; branch defaults to main (tests use their own).
ubuntu{ release: "26.04"; codename: "resolute"; point?: string | undefined; }The Ubuntu release every host runs (point: a point release's image, when pinned).
timezonestringAn IANA time zone, for example "America/New_York".
localestringFor example "en_US.UTF-8".
keyboardstringThe console's keyboard layout, for example "us".
providers?Partial<ProvidersDef>DNS, mail, and ACME providers (spec 046); see ProvidersDef for the defaults.
signers?SignerDef[]Who may approve changes (spec 047): loaded from fleets/<id>/signers.ts.
admin{ user: string; uid: number; github: GitHubIdentity; }The fleet's admin: one person, one account on every host (spec 003).
mcp?{ maxTier?: McpTier | undefined; keys?: string[] | undefined; }The agent layer (spec 030, Article 17): workstations reach each server as ops over SSH, forced to archon mcp --max-tier <maxTier>. Default: tier mutate, the admin's GitHub SSH keys. The destructive tier is never served.
ssh?{ passwordFrom?: string[] | undefined; }SSH (spec 007): networks (CIDR) from which passwords are accepted as well as keys. Default: the private ranges (your LAN and VLANs). [] means keys only.
estate?{ personSources?: string[] | undefined; exports?: ExportJobDef[] | undefined; }The estate graph (spec 090). personSources: the connectors that may create people, in order; the first one connected is the source of truth and the others only link to its people. Default: bamboohr, rippling, gusto, deel, justworks, okta, jumpcloud, microsoft, google (HR systems, then identity providers).
compliance?{ cadence?: CadenceOverrides | undefined; gate?: ComplianceGate | undefined; }Compliance (spec 073). cadence: how often each source of evidence is observed and how late it may be before it is stale (a failing check, SCF MON-02). Default: managed servers every 15 minutes, everything else daily, each stale after twice its cadence, never more than 7 days.
observability?Partial<ObservabilityDef>Local observability limits for every host and workstation (spec 021).
mail?{ to: string; domain: string; tag?: string | undefined; relay?: string | undefined; }Outbound mail (spec 027) and notifications (spec 025). Every server relays its mail (Postfix) through Cloudflare Email Service, from <user>+<host>.<tag>@<domain> (only <domain> onboarded for Email Sending in Cloudflare); mail for local accounts (root, ops) and archon's own messages go to to. Without it, no mail leaves and archon notify is not configured.
network?Partial<NetworkDef>The fallback network facts (spec 009) for a host that is not on a site network (a workstation). A host on the site takes them from its network.
site?SiteDefThe site's network as data (spec 028, Article 21): fleets/<fleet>/site.ts.
telemetry?{ collector?: string | undefined; name?: string | undefined; }A central OpenTelemetry collector (spec 024). Hosts and workstations look for one every 15 minutes, by unicast DNS only (Article 20): this address, else the name (default "otel.localdomain", a UniFi Local DNS record) on port 4318. Until one answers, everything stays local.
web?WebFleetDefHTTPS on every server (spec 032): each answers as <host>.<domain> and its apps as <app>.<host>.<domain>, with one Let's Encrypt certificate per server (the name and its wildcard) through Cloudflare's DNS challenge. Each server keeps its own A records in Cloudflare (private addresses). Without it, servers still answer HTTPS with a self-signed certificate.
services?ServiceDef[]Service accounts for apps, the same on every server (spec 039): Linux system accounts named s-<app>, with fixed UIDs, no password, no shell. An app runs as its account and reaches PostgreSQL as the role of that name.

A fleet with mail and HTTPS, like a real one

HostDefinterface
interface HostDef

A host: one machine of the fleet, in fleets/<id>/hosts/<name>/host.ts. stolos host add <name> --claim (or --mac-address) writes a server's; stolos workstation add a workstation's. What it gets comes from its capabilities; what it is (its MAC, its SSH host keys) is in its registration.ts, from the machine itself (spec 051).

MemberTypeWhat it is
namestringIts name: a DNS label, unique in the fleet.
kind?"server" | "workstation""server" (default): an Ubuntu Server host Archon installs and converges. "workstation" (spec 020): Ubuntu on WSL (or a desktop) where Archon applies only the user-level parts: tools, dotfiles, the archon command.
user?stringWorkstations: the existing account Archon sets up (default: the fleet admin's name).
desktop?booleanWorkstations (spec 036): a graphical desktop, not WSL or a headless machine. VS Code is installed only here; set by stolos workstation add.
mac?stringOptional, and no longer written by archon: the NIC the host network-boots from (lowercase, colon-separated). Since spec 051 the MAC lives in registration.ts, given with --mac-address or reported by the machine; a mac here is still read. Without either, the host is recognized by a claim or its own Boot URI (/boot/<name>/bootx64.efi).
arch"amd64"The CPU architecture (amd64 only, for now).
disk?DiskDefServers: the install disk (default: Ubuntu's LVM layout on the largest disk).
users?UserDef[]Extra accounts beyond the fleet admin and ops.
capabilitiesCapability[]What it gets: foundation() for a server, workstation() for a workstation, plus any more.
guests?GuestDef[]LXD containers and VMs (spec 017).
backup?Partial<BackupDef>Overrides of the default backup policy (spec 016).
observability?Partial<ObservabilityDef>Overrides of the fleet's local observability limits (spec 021).
network?stringThe site network it lives on (spec 028), by name: "Servers". Its IPv6 follows that network.
ipv6?booleanPer-host override of the network's IPv6 (spec 009).
ip?stringIts fixed address (a UniFi Fixed IP), inside its network (spec 028).
dnsName?stringIts unicast DNS name, a UniFi Local DNS record (Article 20): "alpha.localdomain".
switchPort?stringThe switch port it is cabled to: "flex-2.5g/3".
web?{ routes?: Omit<WebRoute, "spec">[] | undefined; }Services this server publishes through its proxy (spec 032).
outOfBand?{ amt?: { address?: string | undefined; notes?: string | undefined; } | undefined; }Out-of-band management (Intel AMT): its address and notes, for the person at the console.
pg?{ instances?: PgInstanceDef[] | undefined; }PostgreSQL instances this server keeps (spec 038).
pgState?PgStateWhat operators recorded on this host (the host's own archon.sql (opt-in pg), spec 038): the clusters Archon created and which are published. Read by loadHosts; never written in a host file.
optIn?Record<string, OptInRecord>Opt-in services and containers an operator turned on or off (spec 040): this machine's archon.sql<name>.json {enabled, by, at}. Read by loadHosts; never written in a host file. Absent means off.
spec`${number}-${string}`The spec that brought it (for a host, usually "004-install").
registration?HostRegistrationWho it is, from fleets/<id>/hosts/<host>/registration.ts (spec 047): read by loadHosts.
