telemetry

Archon's own telemetry (specs 021, 049, 096; Article 27), through IFC TypeScript's signals (runtime/otel, commons 0006-signals): every command is a trace, an archon.run span with one archon.phase span per phase, its results are metrics, and its phases and problems are archon.phase and archon.problem log records in that trace. Every name comes from telemetry/signals.ts and telemetry/events.ts, and the registry below is made from them, so a name that is not declared does not compile.

The pipeline is configured by OpenTelemetry's own variables (OTEL_EXPORTER_OTLP_ENDPOINT, OTEL_SERVICE_NAME, OTEL_RESOURCE_ATTRIBUTES, ...), which the launcher sets to the local Collector with the fleet, host, engine version and commit as resource attributes; without an endpoint it looks for a Collector on localhost:4318 and is silent where none listens. A run continues a trace begun elsewhere when TRACEPARENT is set (an MCP call's _meta.traceparent, an SSH command from the boot machine), and every program it runs through proc is given its TRACEPARENT in turn.

Source: src/archon/core/telemetry.ts

flushEventsfunction
