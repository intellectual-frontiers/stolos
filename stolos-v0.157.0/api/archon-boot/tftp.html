tftp

A read-only TFTP server for PXE (spec 004): UEFI PXE firmware fetches shim over TFTP, shim fetches GRUB, and GRUB its menu, kernel, and initrd, all from the same server. Each read is answered by the same handler as HTTP, so PXE and HTTP Boot serve identical files and menus. RFC 1350 with the blksize (2348), tsize (2349), timeout (2349), and windowsize (7440) options; block numbers roll over past 65535 (Ubuntu's initrd is ~100 MB).

Source: src/archon-boot/tftp.ts

interface TftpOptions

Options for the TFTP server.

MemberTypeWhat it is
port?numberThe UDP port to listen on: the ontology's boot-tftp (69, TFTP's standard port) unless the person chose another.
read(path: string, from: string) => Promise<Uint8Array<ArrayBufferLike> | undefined>Read a file for a client: bytes, or undefined when there is none.
emit(e: ArchonEvent) => voidSpec 049: structured events; the window and boot.log render them.
parseRequestfunction
function parseRequest(msg: Uint8Array<ArrayBufferLike>): { file: string; mode: string; opts: Record<string, string>; } | undefined

Parse a TFTP read request (RRQ): the file, the transfer mode (lowercased) and the options (names lowercased). Undefined for anything else.

negotiatefunction
function negotiate(opts: Record<string, string>, size: number): { out: Record<string, string>; blksize: number; timeout: number; window: number; }

Negotiate options: what we accept, as sent back in the OACK.

serveTftpfunction
function serveTftp(o: TftpOptions): Promise<{ close: () => void; }>

Serve TFTP reads on o.port (all IPv4 addresses). Resolves once bound, with a close to stop it; rejects with a plain explanation when the port is in use or needs privileges.
