delivery-commands

The export delivery commands, on your PC (spec 092):

bun run stolos export list the jobs, how each delivers, and its last run bun run stolos export run <job> make and deliver one job's documents now bun run stolos export schedule <job> create this PC's own scheduled job for it bun run stolos export schedule <job> --remove remove it bun run stolos export credential <name> store a separate send-only credential

#A send-only credential (least privilege)

Stolos only ever submits mail (SMTP: EHLO, AUTH, MAIL, RCPT, DATA, over TLS that it requires); it never opens a mailbox (no IMAP, no POP, no mail API). Give it a credential that can do nothing more:

  • The fleet's own (default): the Cloudflare API token from stolos boot mail-setup, with the one permission "Email Sending: Edit" on the account (Cloudflare Email Service sends only; there is no mailbox to read). Limit it to the sending zone and, if you like, to this PC's address.
  • A tenant's own (email.credential in the job): stolos export credential <name> stores it on this PC only (mail-<name>.json in the secrets folder, backed up by the vault). Use a submission-only account: another Cloudflare token as above, or a provider's SMTP account with reading (IMAP, POP, the mail API) turned off, ideally an app password limited to SMTP. --user gives its SMTP user name.

#Recipients' certificates

Each recipient sends you their S/MIME certificate (public: X.509, RSA, PEM; the .cer or .pem their mail program exports, never the .p12 or .pfx that holds the private key). Put it in the fleet repository, for example fleets/<id>/certs/auditor.pem, and name it in the job. Each recipient gets their own copy, encrypted to their certificate only; one without a usable certificate (missing, expired, for another address) gets nothing, and the run says why.

Source: src/archon/export/delivery-commands.ts

readCredentialfunction
function readCredential(name?: string | undefined): Promise<Credential | undefined>

Read a send-only credential: the fleet's (no name) or a job's own, from this PC's secrets.

exportRunfunction
function exportRun(id: string): Promise<number>

stolos export run <job>: make and deliver the documents now; exit 1 on any problem.

exportListfunction
function exportList(): Promise<number>

stolos export list: each job, its kinds and tenants, how it delivers, its schedule, its last run.

exportSchedulefunction
function exportSchedule(id: string, o?: { remove?: boolean | undefined; dryRun?: boolean | undefined; }): Promise<number>

stolos export schedule <job> [--remove] [--dry-run]: create (or remove) this PC's own scheduled job (kernel jobs.planJob, runtime jobs.installJob and jobs.removeJob). With --dry-run, print the files and commands and change nothing.

exportCredentialfunction
function exportCredential(name: string, user?: string | undefined): Promise<number>

stolos export credential <name> [--user <smtp user>]: read a send-only credential (hidden, or one line on stdin), check it logs in to the relay of a job that names it (nothing is sent), and store it in this PC's secrets folder. Never printed, never logged.
