scope

Spec 082: running in one client's scope. A scope is three environment variables (ARCHON_REPO, ARCHON_FLEET, ARCHON_CLIENT): every path Stolos resolves (P: the repository, the fleet, this PC's state, secrets, and key store) follows them. --client <id> enters a scope for the whole run; the provider's console and clients summary enter one client at a time with withClient, which lets work for one client run only when no other client's work is in progress, so two clients' paths are never live at once.

Source: src/archon/clients/scope.ts

SCOPE_VARSconst
const SCOPE_VARS: readonly ["ARCHON_REPO", "ARCHON_FLEET", "ARCHON_CLIENT"]

The variables that make a scope.

clientEnvfunction
function clientEnv(c: Client): Record<"ARCHON_CLIENT" | "ARCHON_FLEET" | "ARCHON_REPO", string>

A client's scope, as environment variables (also for a command run in its checkout).

enterClientfunction
function enterClient(c: Client | undefined): void

Enter a client's scope for the rest of this process (undefined: leave every scope).

withClientfunction
function withClient<T>(c: Client, fn: () => Promise<T>): Promise<T>

Run fn in client c's scope. Work for the same client may overlap (a page and the facts it reads); work for another client waits until none is left. When the last holder leaves, the scope before it is restored.

activeClientfunction
function activeClient(): string | undefined

The client whose scope is live now (for tests), or undefined.
