guides

The guides: each is the @module documentation of the module beside the code it explains (so IFC Docs renders it, with its Mermaid diagrams, and it changes in the same commit as the code). The build extracts each one into the engine's assets as docs/<name>.md, so the man pages, the welcome page, both consoles, explain, and stolos docs read the same text offline.

Source: src/archon/core/guides.ts

GuideDefinterface
interface GuideDef

One guide: its name, its title, who reads it, and the module whose documentation it is.

MemberTypeWhat it is
namestringIts name: stolos docs <name>, /guide/<name>, docs/<name>.md in the assets.
titlestringIts title.
whystringWhat it is for, in one line.
modulestringThe module (repository path) whose @module JSDoc is the guide.

docsAreafunction
function docsArea(module: string): string

The area of the documentation site a module opens (spec 070 FR-002): docs.config.ts makes each guide's module the first entry point of the area of this name, so IFC Docs shows the guide as that area's overview, at api/<area>/index.html. The name is the module's path under src/ with / as - and without /mod.ts or .ts; the overview module (src/mod.ts) opens overview.

guideUrlfunction
function guideUrl(name: string, version?: string): string

A guide's page online, for this engine's version: its area's overview.

guideReffunction
function guideRef(name: string): string

How a message points to a guide: the command that shows it, here and offline.

guideMarkdownfunction
function guideMarkdown(source: string): string

A module's @module JSDoc as Markdown: its first doc comment, without the leading * and the tags. *\/ in it (which would end the comment) is written escaped in the source and restored here.

guideCommentfunction
function guideComment(markdown: string): string

A guide's Markdown as a doc comment (the reverse of guideMarkdown).
