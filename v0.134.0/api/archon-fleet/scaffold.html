packageJsonTextfunction
function packageJsonText(tag: string, source?: string): string

A fleet repository's package.json (spec 096 FR-006): the engine by Git at its tag (github:intellectual-frontiers/stolos#v<version>; bun.lock pins the tag's commit and its integrity), and the commands bun run stolos ... and bun run archon .... On Node 26 the same files run as node --import @intellectual-frontiers/commons/ts/node stolos.ts.

On your PC, use\n// `bun run stolos`.\nimport { run } from \"@intellectual-frontiers/stolos/archon/main\";\n\nawait run();\n"

VS Code's suggested extensions: Mermaid in Markdown previews, GitHub Actions, YAML.

GITATTRIBUTES_TEXTconst
const GITATTRIBUTES_TEXT: "# Written by stolos (spec 062): every text file keeps LF on every system, as stolos\n# and bun fmt write them (Git for Windows would otherwise check them out with CRLF).\n* text=auto eol=lf\n"

Line endings Git keeps whatever the PC (spec 062): every text file LF, as stolos and bun fmt write them. Git for Windows would otherwise check files out with CRLF: a shell script would not run on Linux or macOS, and a file in stolos's fixed form (signers.ts, registration.ts) would not read back as it.

scaffoldFilesfunction
function scaffoldFiles(tag: string, source?: string, slug?: string): Record<string, string>

The files of a fleet repository, by path relative to its root; slug is its GitHub owner/name. bun.lock is not among them: bun install writes it (scaffoldRepository's caller runs it).

installEnginefunction
function installEngine(repo: string): Promise<{ ok: boolean; why?: string | undefined; }>

Install the engine the checkout pins, exactly as bun.lock holds it (bun install --frozen-lockfile): what runs bun run stolos, and what VS Code reads to check fleet.ts. Returns why not, if not (an integrity error is E046-LOCK-INTEGRITY).
