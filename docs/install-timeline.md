# What happens during an install

From power-on to `Ready`, in order. The middle column is what the boot server's window (and
`%LOCALAPPDATA%\archon\boot\boot.log`) shows; the last column is where to look when a step fails.

| #  | Step                                                                                                                                     | Boot server shows                                                                                                                                                                          | Where to look                                                                                         |
| -- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| 1  | The firmware asks DHCP for an address and the network boot server (your router answers: next-server = the PC, boot file `bootx64.efi`)   | nothing yet                                                                                                                                                                                | the server's screen; your router's DHCP settings                                                      |
| 2  | Firmware downloads Ubuntu's signed shim over TFTP; shim downloads Ubuntu's network GRUB (Secure Boot checks both)                        | `TFTP bootx64.efi`, `TFTP grubx64.efi`                                                                                                                                                     | boot server window; firewall (UDP 69)                                                                 |
| 3  | GRUB asks for its menu; the boot server recognizes the machine (Boot URI, claim, or learned MAC)                                         | `claimed by alpha` or `alpha: armed, starting its install`                                                                                                                                 | `deno task stolos boot status`                                                                        |
| 4  | GRUB downloads the kernel and installer initrd (about 120 MB) over TFTP                                                                  | `TFTP linux`, `TFTP initrd`                                                                                                                                                                | boot server window                                                                                    |
| 5  | The installer boots and downloads the Ubuntu image (2.9 GB) over HTTP                                                                    | `installer image (whole)`                                                                                                                                                                  | the server's screen; firewall (TCP 8080); the boot server warns after 3 minutes if HTTP never arrives |
| 6  | The installer fetches alpha' install config; the boot server fills in the secrets (password hash, deploy key, SSH host keys, mail token) | `install config sent (network on <mac>) with its ...`                                                                                                                                      | boot server window                                                                                    |
| 7  | Unattended install: disk, Ubuntu, kernel, updates, configuration                                                                         | `installer: partitioning the disk`, `copying Ubuntu to the disk`, `installing the kernel`, `installing updates`, `configuring the installed system`; any failed step as `✗ installer: ...` | on the host afterwards: `/var/log/installer/`                                                         |
| 8  | The installer records the network boot entry, reports done, and reboots                                                                  | `install finished; disarmed`, `this PC trusts its SSH host keys for ...`                                                                                                                   | boot server window                                                                                    |
| 9  | First boot (cloud-init): installs Deno, clones the repository with the deploy key                                                        | `First boot: installing Deno, cloning the repository`                                                                                                                                      | on the host: `/var/log/archon-first-boot.log`                                                         |
| 10 | `archon first-boot`: apply (packages and PPAs, accounts, files, units), mail token, GitHub, tools, dotfiles, verify, record              | one line per phase, for example `✓ Tools: ...`, `✓ Verify: 44 passed`                                                                                                                      | on the host: `/var/log/archon/<time>.log` (the run log), `/var/log/archon-first-boot.log`             |
| 11 | The first record is pushed to GitHub (`archon.sql alpha/installed.json`)                                                                 | `✓ Ready: 44/44 checks · ssh alpha`, or `✗ Done with problems: ...`                                                                                                                        | `installed.json` (`ok`, `problems`)                                                                   |

Timing on real hardware: steps 1 to 6 take a minute or two (mostly the image download), the install
itself a few minutes, the first boot a minute or two.

After `Ready`, the host converges to GitHub every 15 minutes by itself (`archon-reconcile`), and
`ssh alpha` connects without questions.
