not-observed

Spec 117-adopted-in-status: "no evidence" is not a failure. A control that went from no evidence to a failing status, where nothing of it was observed (or only something stale), is waiting for an observation: it is shown as not observed yet (the hourglass, the "not set up yet" class of spec 105-calm-output), with the one command that observes it, never as a warning that says it failed. This decides and words it; it never changes the evidence, a control's status, a requirement's status or the gate (the display only).

Source: src/archon/compliance/not-observed.ts

NEVER_OBSERVED_CHECKconst
const NEVER_OBSERVED_CHECK: "Observed by Stolos"

The check of the result an unobserved adopted machine or device carries (spec 067-adopt): it says nothing was observed.

NO_EVIDENCE_CODEconst
const NO_EVIDENCE_CODE: "P117-NO-EVIDENCE"

The explain code of a waiting observation (stolos explain P117-NO-EVIDENCE).

DISK_CHECKconst
const DISK_CHECK: "The disk is encrypted"

The title of the adopted machines' disk policy, whose reason (the probe's fact) the fix says.

DISK_REASONconst
const DISK_REASON: "the disk's encryption needs the probe's disk_encryption fact (BitLocker on Windows, FileVault on macOS, LUKS on Linux): "

Why the disk's encryption is not observed where it is not: the probe's fact (spec 117-adopted-in-status FR-008).

isNotObservedfunction
function isNotObserved(c: ControlChange): boolean

Whether a control's change is "no evidence" rather than a failure: it went from no evidence to a failing status and none of its changed evidence is a current failure (a check observed within its service level that failed). An empty list of evidence, a stale observation and the never-observed result all wait for an observation.

notObservedWordsfunction
function notObservedWords(c: ControlChange): { text: string; fix: string; }

What a waiting control says: not observed yet (or not observed recently, where all that exists is stale), and the one fix line.
