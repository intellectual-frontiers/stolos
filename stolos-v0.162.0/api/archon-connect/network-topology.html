network-topology

Spec 110-network-assets FR-007, FR-008: the topology the uplink edges give, laid out by a typed function and drawn as SVG on the server (no graph library, no script). The gateway is at the top, below it the switches and access points it connects, and under each device its clients (a few by name, then "+N more"). A device with no uplink in the API's answer that is not a gateway is not guessed a parent: it is drawn apart, in a row of its own, and the page says why.

Source: src/archon/connect/network-topology.ts

Topologyinterface
interface Topology

The trees of a view: those that start at a gateway or a device the API gave no parent to, and the devices drawn apart.

MemberTypeWhat it is
rootsTopoNode[]Trees from the top: a gateway, or a device with no uplink (a gateway first).
orphansTopoNode[]Devices that are not a gateway and have no uplink in the answer (no edge is guessed).
notesstring[]What the drawing leaves out and why.
topologyfunction
function topology(view: NetworkView, o?: { maxClients?: number | undefined; }): Topology

The trees of a network view: the uplink edges give the parents, the clients hang under their device.

Layoutinterface
interface Layout

A drawing: every node with its place, the links between a parent and its children, and the size.

MemberTypeWhat it is
nodesTopoNode[]Every node, with x, y, w and h set (the centre of the node).
links{ from: TopoNode; to: TopoNode; }[]A parent to a child.
widthnumberThe width of the drawing.
heightnumberThe height of the drawing.
orphanY?numberWhere the row of devices without an uplink starts, when there is one.
layoutTopologyfunction
function layoutTopology(t: Topology): Layout

Lay a topology out: a leaf takes the next slot from the left, a parent is centred over its first and last child, a level is a row. The devices without an uplink are laid out apart, below the trees, with a gap.

classGlyphfunction
function classGlyph(c: "client" | DeviceClass): string

The glyph of a class: strokes in a 16 by 16 box (currentColor), the same everywhere a class is shown (the machines table, the topology, a device's page).

glyphSvgfunction
function glyphSvg(c: "client" | DeviceClass, size?: number): string

A glyph as a small inline SVG (for a table cell or a heading).

topologySvgfunction
function topologySvg(l: Layout, o?: { label?: string | undefined; href?: ((n: TopoNode) => string | undefined) | undefined; }): string

The drawing as SVG text. The colours are the console's own variables (with fallbacks), so it follows light and dark; every label is escaped. href makes a node a link (a device's page).
