Archon's own telemetry (specs 021, 049; Article 27), through Deno's built-in OpenTelemetry: every command is a trace (one span per phase) and its results are metrics. Console output (errors, --json) is exported by Deno as logs linked to the trace; the journal reaches the Collector through journald. Every name comes from telemetry/signals.ts.

The launcher sets OTEL_DENO and points OTLP at the local Collector, with the fleet, host, engine version, and commit as resource attributes. A run continues a trace begun elsewhere when TRACEPARENT is set (an MCP call's _meta.traceparent, an SSH command from the boot machine). Without OTEL_DENO, or if the API cannot load, everything here is a no-op.

flowchart LR
  run["an archon run"] --> trace["a trace: its phases as spans"]
  run --> events["its problems as log records"]
  trace --> col{"collector"}
  events --> col
  col -->|on the host| local["the local OpenTelemetry Collector"]
  col -->|first boot| boot["the boot server (/otlp)"]
  local -->|opt-in| ui["OpenObserve"]

Interfaces

I
SpanContext

A span's identity, as a W3C traceparent carries it.

  • isRemote: boolean

    True when the context came from another process.

  • spanId: string

    The parent span's ID: 16 lowercase hex digits, not all zero.

  • traceFlags: number

    Trace flags (bit 0: sampled).

  • traceId: string

    The trace ID: 32 lowercase hex digits, not all zero.
