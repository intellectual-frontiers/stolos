Spec 074: compliance impact at the point of change. Given the fleet at a base commit and at a head commit (or the working tree), which SCF controls the change weakens or strengthens, with the framework requirements the SCF Council maps each to. stolos apply shows it before it commits; stolos compliance impact prints it (--json, --markdown); a fleet repository's pull requests get it as one comment (workflow.ts).

Two kinds of change are found:

  1. Model changes: IMPLEMENTATIONS is Stolos's own statement of which SCF control each model setting implements and which direction weakens it (unattended upgrades off: VPM-08; SSH passwords accepted from more networks: IAC-14; a port opened: NET-02; a host out of backups: BCD-24). Each side's model is loaded and each host's plan resolved, then reduced to FleetFacts, which the declarations compare.
  2. Evidence changes: the observations Git records (adopted machines, devices, connected accounts) and the fleet's control packs, each side read as compliance drift reads them (drift.ts), compared per control.
flowchart LR
  base["base commit"] --> fb["model: facts"] & eb["observations and packs: evidence"]
  head["head commit, or the working tree"] --> fh["model: facts"] & eh["observations and packs: evidence"]
  fb & fh -- "IMPLEMENTATIONS (Stolos's declarations)" --> mc["weakens / strengthens, per control"]
  eb & eh -- "compareViews (drift.ts)" --> ec["status changes, per control"]
  mc & ec --> ctl["affected SCF controls"]
  ctl -- "SCF STRM (catalog, when cached)" --> fw["framework requirements"]
  mc --> gate{"compliance.gate (base's fleet.ts)"}
  gate -- "allow, accepted risk, approval" --> ok["allowed"]
  gate -- "none" --> block["blocked"]

The gate (compliance.gate in fleet.ts, ComplianceGate) is read from the base side, so a change cannot turn off the gate that judges it. With block: "weakens", a weakening is allowed only when the gate's allow names it, when fleets/<fleet>/controls/accepted.ts accepts it (policy: "impact/<key>", until a date), or when it is approved: a commit in the change carries the trailer Compliance-Approved: <keys> and a good signature by one of the base's signers (signers.ts). stolos apply --approve <keys> writes that trailer into the commit it signs.

Interfaces

I
AffectedControl

One affected SCF control, with what moved it.

  • changes: ModelChange[]

    The model changes.

  • direction: Direction

    Weakened (anything weakens it), else strengthened.

  • evidence: ControlChange

    The evidence change, when its observed status changed.

  • id: string

    The SCF id.

  • name: string

    Its SCF name.

  • requirements: Partial<Record<FrameworkId, string[]>>

    Framework requirements SCF maps it to (when the catalog is cached).

I
Approval

A recorded approval: a signed commit's Compliance-Approved: trailer.

  • commit: string

    The commit ("(this commit)" for the one stolos apply --approve is about to sign).

  • covers: string[]

    What it approves: keys (see changeKeys), or "all".

  • signer: string

    Who signed it (the signer's name in signers.ts).

I
CadenceFact

A cadence, as the facts keep it.

  • every: string

    How often ("15m", "1d").

  • everyMs: number

    every in milliseconds.

  • staleAfter: string

    Its service level.

  • staleAfterMs: number

    staleAfter in milliseconds.

I
ComplianceGate

The gate (compliance.gate in fleets/<fleet>/fleet.ts): whether a change that weakens a control may be committed (stolos apply) or merged (the pull request's check). Default: never block, only show.

  • allow: string[]

    Weakenings that never block: a declaration's id ("firewall-ports"), a declaration on one subject ("updates/beta"), or an SCF control ("NET-02").

  • block: "weakens" | "never"

    "weakens": refuse a change that weakens a control unless allowed; "never" (default): show only.

  • evidence: boolean

    Also block when observed evidence turns a control to fail (default false: shown only).

I
Finding

What a declaration finds when it compares two sides.

  • direction: Direction

    Which way.

  • what: string

    The change, in words: "turns off unattended upgrades".

I
FleetFacts

What a fleet's model says about the settings that implement controls.

  • agentTier: McpTier

    The tier agents get over MCP (spec 030).

  • cadence: Record<string, CadenceFact>

    The evidence cadences (spec 073): each source, and each connector the fleet sets.

  • fleet: string

    The fleet's id.

  • gate: ComplianceGate

    The gate this side sets (spec 074).

  • hosts: Record<string, HostFacts>

    Each host's facts, by name.

  • problems: string[]

    Hosts whose plan could not be resolved, with why.

I
GateItem

One weakening the gate judged.

  • allowedBy: string

    What allowed it, when something did.

  • keys: string[]

    Its keys: the declaration, the declaration on its subject, the SCF control.

  • what: string

    The change, in words, with its subject.

I
GateResult

The gate's verdict.

  • block: "weakens" | "never"

    The mode in force.

  • blocked: boolean

    Whether the change is refused.

  • items: GateItem[]

    Each weakening, and what allowed it.

I
HostFacts

What one host's resolved plan says about the settings that implement controls.

  • admins: string[]

    The accounts with administrator rights.

  • backup: boolean

    The daily backup timer (spec 016).

  • backupKeep: number

    How many archives are kept.

  • backupScope: string[]

    What the backup holds: paths, and "guest <name>" for each durable guest (spec 044).

  • etckeeper: boolean

    /etc kept in Git by etckeeper (spec 033).

  • firewall: boolean

    ufw installed and enabled (spec 008).

  • kind: "server" | "workstation"

    Server or workstation.

  • osquery: boolean

    osquery, for fleet-wide questions (spec 042).

  • ports: string[]

    The ports open in the host's firewall, as "22/tcp".

  • sshPasswords: string[]

    Where sshd accepts passwords (spec 007): the networks of its Match block, "anywhere" when it accepts them outside one, [] for keys only; undefined when Stolos does not configure sshd on the host.

  • updates: boolean

    Unattended upgrades: the package, and apt-daily-upgrade.timer enabled (spec 009).

  • problems: string[]
