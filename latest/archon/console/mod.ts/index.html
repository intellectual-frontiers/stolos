The Stolos Console

The fleet in your browser, on your PC only (spec 066). Every machine (managed, adopted, in a cloud), the clouds, one SQL question to every machine, the changes waiting and who may approve them, and the stolos commands as forms.

bun run stolos console

How you sign in

There is no password and no new key. The terminal prints a launch link that works once, for two minutes; whoever can read your terminal is you. The console answers only on 127.0.0.1 and localhost (another web page cannot reach it), and only forms from its own pages may run commands.

Before it starts, it asks GitHub (with gh) whether your account may push to the fleet repository: the console is for the fleet's operators. Offline, --no-github skips that check.

Passphrases and tokens

A command that needs a secret (a signing key's passphrase, a cloud token, the backup passphrase) asks for it in the terminal where the console runs, never in the browser. One command runs at a time, so the terminal is never asked two things at once.

What it offers, and what it does not

PageWhat it is for
OverviewWhat needs you: failing checks, failing policies, commits servers will refuse
MachinesEvery machine, filterable; download it as CSV, and every result with SCF as JSON
CloudsEach cloud account's assets and posture
Ask every machineOne osquery SELECT to every machine, as one table
Changes, TrustWhat is waiting for approval, the history, and who may approve
ActionsThe stolos commands, grouped, each as a form with its output live

Commands that change keys (keys setup, keys rotate, keys lost) and vault restore stay in the terminal: they are rare, and each deserves your full attention.

The REST API (read-only)

The console also answers JSON under /v1/ (spec 094), for scripts and tools on this PC. It is read-only (GET and HEAD; anything else is 405), on 127.0.0.1 only, and for the signed-in console session: there are no API keys. A request without the session's cookie gets 401. A local tool uses the cookie your browser holds (stolos_session, from the browser's developer tools).

RouteWhat it answers
/v1/What it serves
/v1/openapi.jsonThe OpenAPI 3.1 document, generated from the estate schema
/v1/<table or view>Every estate table and view: { items, limit, offset, total }
/v1/finding?format=ocsfThe findings as OCSF Compliance Findings (or Accept: application/vnd.ocsf+json)
/v1/oscal/<document>component-definition, system-security-plan, assessment-results, poam
/v1/evidence/The evidence bundles on this PC (stolos evidence export), to download

A list takes limit (default 100, at most 1000), offset, and an equality filter on any of its columns: ?status=active, ?admin=true. Booleans are true and false. Every value is bound as a parameter, never written into the SQL.

curl -s --cookie "stolos_session=<the cookie's value>" \
  "http://127.0.0.1:8091/v1/user_account?admin=true&mfa=false&limit=20"
