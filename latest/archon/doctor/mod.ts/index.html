Troubleshooting

If the boot machine itself is lost, see disaster recovery.

Start with deno task stolos boot doctor on the boot machine, and archon doctor (network and email) and archon verify (the host's configuration) on a host: each prints the fix for each problem it finds. When asking for help, send %LOCALAPPDATA%\stolos\boot\boot.log (boot machine), and from the host /var/log/archon-first-boot.log and the run log a failure names.

Network boot

Symptom Cause Fix
The server's firmware shows no network boot entry the network stack is off BIOS: Advanced → Network Stack Configuration: enable Network Stack and IPv4 PXE Support
The server boots its disk; the boot server shows nothing it did not network-boot, or the router does not send next-server pick UEFI PXE IPv4 from the boot menu (F7 on an MS-01); check Network Boot on the network the server is on (boot machine)
TFTP netboot.xyz-snponly.efi: serving bootx64.efi instead the router's boot file name is an old value set the router's Filename to bootx64.efi (the install works meanwhile)
Nothing arrives at all, from any machine Windows firewall, or something else holds UDP 69 deno task stolos boot doctor; stop Tftpd64
unknown machine ...: menu of armed hosts and the server sits at a menu the machine is not recognized: no claim, no learned MAC deno task stolos boot arm alpha --claim and reboot it, or pick the host in the menu
alpha: not armed, booting its own disk the install already ran, or was never armed deno task stolos boot arm alpha (add --claim or --mac-address <mac> if it never installed), or boot reinstall alpha
The installer stops at (initramfs) with wget: can't connect to remote host ... Connection timed out TCP 8080 is blocked between the server and the PC (TFTP is UDP and got through) Windows: the HTTP firewall rule (boot machine); UniFi: the zone firewall needs an allow policy from the servers' zone to the boot machine, TCP 8080 (and UDP 69) (boot machine). Test from the (initramfs) prompt: wget -O- http://<pc>:8080/grub/grub.cfg, then Ctrl+Alt+Del
loaded the installer over TFTP but has not reached HTTP port 8080 the same the same
The wrong address shows in boot serve the PC has several adapters (WSL, Hyper-V, VPN) deno task stolos boot serve --address <pc>
UDP port 69 is in use another TFTP server stop Tftpd64 or Windows Deployment Services

Install and first boot

Symptom Cause Fix
✗ installer: ... in the boot server window an installer step failed on the host (console): /var/log/installer/; re-arm and re-install after fixing the cause
✗ Done with problems / installed.json has "ok": false a first-boot step failed ssh alpha, then sudo tail -60 /var/log/archon-first-boot.log; usually sudo archon update finishes it
A tool is missing and verify says command not found its install failed and was rolled back (smoke test) sudo archon tools sync shows why
fish or the Archon prompt is missing after an install dotfiles waited for chezmoi, which failed sudo archon update, then log in again
ppa:... has no builds for Ubuntu 26.04 warning that PPA has not published for this release yet nothing: Ubuntu's package is used until it does

SSH and GitHub

Symptom Cause Fix
REMOTE HOST IDENTIFICATION HAS CHANGED an older install made its own host keys, or the PC's known_hosts predates host identities deno task stolos boot arm <host> (it writes the host's real keys into known_hosts), or ssh-keygen -R <host>
Permission denied (publickey) when you type a password you are connecting from outside the local networks (or the host predates passwords on the LAN) use your SSH key; on the host, sudo archon update brings the LAN password rule; check ssh.passwordFrom in fleets/<fleet>/fleet.ts
fleet init: no SSH keys on GitHub your GitHub account has none accept its offer to add this PC's key, or add one at https://github.com/settings/keys
git commit on the PC: Author identity unknown git has no name or address fleet init sets them for the checkout; or git config user.name ... and git config user.email <id>+<login>@users.noreply.github.com
boot reinstall: does not answer over SSH the host is off, hung, or on another address power it on and pick network boot once (F7); it is armed already
boot reinstall: is durable or of unknown data class it holds end users' data that exists nowhere else (or could not be asked): Article 23 make sure its data is safe elsewhere (archon data on the host), then repeat with --confirm-destroy <host>

Updates

Symptom Cause Fix
could not reach the Ubuntu archive; the next reconcile tries again DNS or the network failed for longer than apt's retries (spec 009) nothing, usually; if it persists: resolvectl query archive.ubuntu.com, getent ahostsv4 archive.ubuntu.com, and the router's upstream DNS
apt errors list only IPv6 addresses (2620:..., Network is unreachable) the network has no IPv6 and an A lookup failed upstream network: { ipv6: false } in fleets/<fleet>/fleet.ts (this fleet has it), then sudo archon update
snap install ...: the Snap Store did not answer api.snapcraft.io times out from this network nothing: the next reconcile retries
The login banner lists pending updates they install at the next daily run nothing; or sudo unattended-upgrade -v now
46 updates can be applied immediately stays the host predates daily stable updates sudo archon update (writes /etc/apt/apt.conf.d/52archon-updates)

Notifications

Symptom Cause Fix
mail is not configured or no relay token the server has no Cloudflare token on the PC: deno task stolos boot mail-setup (once), then deno task stolos boot mail-push <host>
Cloudflare refused the API token the token was deleted, expired, or lacks Email Sending: Edit create a new account API token (Email Sending, Edit), deno task stolos boot mail-setup, mail-push each server
Cloudflare refused the sender: its domain is not onboarded example.net (mail.domain) is not onboarded for Email Sending in that account Cloudflare: Compute > Email Service > Email Sending > Onboard Domain > example.net
archon doctor: the domain is missing SPF, DKIM, DMARC, or bounce MX onboarding not finished, or the records were changed wait 15 minutes after onboarding; Email Sending > Settings shows each record
smtp.mx.cloudflare.net:465: timed out outbound TCP 465 is blocked allow it in the router's firewall (UniFi: from the Servers zone to the internet)
mail to <address> bounced Cloudflare refused one message for good journalctl -t postfix/smtp shows Cloudflare's answer
archon notify status or mailq shows messages waiting Cloudflare was unreachable nothing: both retry; sudo archon notify flush and sudo postqueue -f retry now
too many login messages the same user logs in from many addresses each user, address, and method is reported at most once an hour
