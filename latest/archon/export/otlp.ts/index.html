archon/export/otlp.ts

Spec 092: OCSF events as OpenTelemetry logs, in the OTLP/HTTP JSON encoding: the body of an ExportLogsServiceRequest that any OTLP receiver (a Collector, an observability backend) accepts at /v1/logs. Only the request body is built here; sending it is delivery's job.

Each OCSF event is one LogRecord (the OpenTelemetry logs data model):

  • body: the event itself, as a structured value (a map);
  • eventName: ocsf.<class> (for example ocsf.compliance_finding), so it is an Event in OpenTelemetry's sense;
  • attributes ocsf.class_uid and ocsf.category_uid;
  • timeUnixNano: the event's time; severity: INFO, WARN for a finding that is not a pass.

The resource says who produced it: service.name stolos, its version, and the fleet (service.namespace).

With entities, inventory also becomes OpenTelemetry entity events (entity.state, a Development-status part of the specification), one per machine (host) and per other node: off by default, since receivers may not understand them yet. People and accounts are never entity events. The entity's type is the attribute entity.type; its identity and description (maps) are the record's body, entity.id and entity.description, since IFC TypeScript's attributes hold no maps.

The request is encoded by IFC TypeScript's kernel (otlp.encodeLogs).
