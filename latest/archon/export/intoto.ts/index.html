Spec 092: an evidence bundle (spec 072) as an in-toto Statement v1, and the DSSE envelope that carries a signed one.

  • subject: the bundle file (its name and SHA-256), then each item in it, named by its path in the bundle (objects/<sha256>), with its kind, name, and time as annotations.
  • predicateType: {@link EVIDENCE_BUNDLE_PREDICATE}. No predicate in the in-toto attestation framework's list fits a set of compliance evidence (SLSA Provenance describes a build, Test Result one test run, SCAI attributes of an artifact), so Stolos defines its own, below.
  • predicate: the manifest's summary (an {@link EvidenceBundlePredicate}).

The statement is unsigned. It is IFC TypeScript's (kernel dsse.statement); a signer wraps it in a DSSE envelope with kernel dsse.signStatement, and a verifier checks it with dsse.verifyStatement. Signing a bundle stays spec 072's job (ssh-keygen -Y sign over the manifest).

Stolos's predicate type for an evidence bundle's summary.

interfaceEvidenceBundlePredicate

export interface EvidenceBundlePredicate {
  /** The bundle format. */
  format: string;
  /** The fleet. */
  fleet: Manifest["fleet"];
  /** The period. */
  period: Manifest["period"];
  /** When the bundle was made. */
  created: string;
  /** The Stolos version that made it. */
  stolos: string;
  /** Who signed the manifest. */
  signer: string;
  /** The manifest, and where its signature is. */
  manifest: { name: string; digest: { sha256: string }; signature: string; namespace: string };
  /** The hash chain's head. */
  head: string;
  /** How many items, in all and by kind. */
  items: { total: number; by_kind: Record<string, number> };
  /** Evidence that could not be included, and why. */
  omitted: string[];
}
