archon/install/bun.ts

The pinned Bun (spec 096-bun-runtime FR-007): the runtime every host, the boot server and the operator's PC run the engine with, and how a fleet checkout gets its engine.

  • The pin: one Bun version, and the SHA-256 of its release archive for each platform, kept in the engine's core/bun-pin.ts. The first boot (render/autoinstall.ts, also run by stolos host bootstrap) downloads the archive for its machine, checks its SHA-256 before unpacking it, and links /usr/local/bin/bun. Raising the pin is a change to that file, reviewed like any other.
  • The engine in a checkout: a fleet repository depends on the engine's release tarball by its URL (package.json), and bun.lock holds its integrity. bun install --frozen-lockfile installs exactly that, or stops (E046-LOCK-INTEGRITY): the lock is the control.
  • The launcher (/usr/local/bin/archon, capabilities/cli.ts) runs the checkout's archon.ts with Bun, and with Node 26 where Bun is not installed.

functionbunInstallShell

export function bunInstallShell(): string

A POSIX shell fragment that installs the pinned Bun on Linux (x86-64 or ARM64) unless that version is already there: the archive for this machine (the baseline build where the CPU has no AVX2), its SHA-256 checked before it is unpacked, then /usr/local/bin/bun. It needs curl and unzip, and fails (with set -e) on any mismatch.
