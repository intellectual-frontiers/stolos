What happens during an install

From power-on to Ready, in order. The middle column is what the boot server's window (and %LOCALAPPDATA%\stolos\boot\boot.log) shows; the last column is where to look when a step fails.

#StepBoot server showsWhere to look
1The firmware asks DHCP for an address and the network boot server (your router answers: next-server = the PC, boot file bootx64.efi)nothing yetthe server's screen; your router's DHCP settings
2Firmware downloads Ubuntu's signed shim over TFTP; shim downloads Ubuntu's network GRUB (Secure Boot checks both)TFTP bootx64.efi, TFTP grubx64.efiboot server window; firewall (UDP 69)
3GRUB asks for its menu; the boot server recognizes the machine (Boot URI, claim, or learned MAC)claimed by alpha or alpha: armed, starting its installbun run stolos boot status
4GRUB downloads the kernel and installer initrd (about 120 MB) over TFTPTFTP linux, TFTP initrdboot server window
5The installer boots and downloads the Ubuntu image (2.9 GB) over HTTPinstaller image (whole)the server's screen; firewall (TCP 8080); the boot server warns after 3 minutes if HTTP never arrives
6The installer fetches alpha' install config; the boot server fills in the secrets (password hash, deploy key, SSH host keys, mail token)install config sent (network on <mac>) with its ...boot server window
7Unattended install: disk, Ubuntu, kernel, updates, configurationinstaller: partitioning the disk, copying Ubuntu to the disk, installing the kernel, installing updates, configuring the installed system; any failed step as ✗ installer: ...on the host afterwards: /var/log/installer/
8The installer records the network boot entry, reports done, and rebootsinstall finished; disarmed, this PC trusts its SSH host keys for ...boot server window
9First boot (cloud-init): installs the pinned Bun, clones the repository with the deploy key, installs the engine bun.lock holdsFirst boot: installing Bun, cloning the repositoryon the host: /var/log/archon-first-boot.log
10archon first-boot: apply (packages and PPAs, accounts, files, units), mail token, GitHub, tools, dotfiles, verify, recordone line per phase, for example ✓ Tools: ..., ✓ Verify: 44 passedon the host: /var/log/archon/<time>.log (the run log), /var/log/archon-first-boot.log
11The first record is pushed to GitHub (archon.sql alpha/installed.json)✓ Ready: 44/44 checks · ssh alpha, or ✗ Done with problems: ...installed.json (ok, problems)

Timing on real hardware: steps 1 to 6 take a minute or two (mostly the image download), the install itself a few minutes, the first boot a minute or two.

After Ready, the host converges to GitHub every 15 minutes by itself (archon-reconcile), and ssh alpha connects without questions.
