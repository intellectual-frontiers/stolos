Spec 049-telemetry (Article 27): events are structured at their source. Each event has a declared name (below), a severity, the host and address it is about, attributes, and a message; it is recorded as an OpenTelemetry log record. Anything a person reads (the boot server's window, boot.log) is a rendering of these records, never the source: the window's icons, colors, and de-duplication come from the event's name and attributes, not from parsing its text.

Interfaces

I
ArchonEvent

One event: what happened, where, and in which trace (an OpenTelemetry log record).

  • address: string

    The client's address (client.address).

  • attrs: Record<string, string | number | boolean>

    Structured details.

  • host: string

    The host it is about.

  • message: string

    What happened, in plain words.

  • name: EventName

    Its name.

  • severity: Severity

    Its severity, when not the usual one.

  • spanId: string

    The span it belongs to.

  • time: number

    Milliseconds since the epoch (default: now).

  • traceId: string

    The trace and span it belongs to (W3C ids, hex).

I
EventSpec

What an event means.

  • description: string

    What it says happened.

  • severity: Severity

    Its usual severity.

I
OtlpKeyValue

One OTLP attribute: a key and its value.

  • key: string

    The attribute's name.

  • value: OtlpAnyValue

    Its value.

| Record<never, never>

An OTLP AnyValue in the OTLP/HTTP JSON encoding: a 64-bit integer is a decimal string, a map is a list of key-values, and an empty object is a null (spec 092 adds arrays and maps, for structured log bodies).
