The boot machine's secret store (spec 003, Article 13): a per-user folder outside the repository (%APPDATA%\stolos\secrets on Windows, ~/.config/stolos/secrets elsewhere). Holds the admin password hash, each host's deploy key, and install tokens. Nothing here is ever committed.

writeSecret(
path: string,

): Promise<void>

Write a secret readable only by this user (POSIX 0600; Windows: inheritance removed and full control for this user only, icacls). Every secret write in Archon goes through here (spec 029): it records the change in the ledger, so the vault knows what is newer than the last backup. Unchanged content is not rewritten (and is not a change).

Interfaces

I
InstallToken

One armed install (the boot machine's own record).

  • addresses: string[]

    Addresses the host was installed from (its old SSH host keys are forgotten for each).

  • armed: string

    When the token was issued (ISO time).

  • claimUntil: string

    boot arm --claim: until then, the next unknown machine to network-boot becomes this host.

  • confirmDestroy: true

    Spec 051: a person repeated the host's name with --confirm-destroy: this one install may erase disks that are not blank (otherwise the installer stops).

  • done: string

    The installer reported completion; the token is spent.

  • firstUse: string

    First time the host fetched its install config; the token then lives 2 hours.

  • host: string

    The host.

  • mac: string

    The MAC the host network-booted from, as GRUB reported it.

  • reinstall: true

    boot reinstall reached this host over SSH (its registered keys) and rebooted it into this install: a machine with this MAC holds this host already.

  • token: string

    The random token in its install URLs.
