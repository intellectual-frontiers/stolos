data

044-durable (Article 23): archon data shows whether this server is durable or ephemeral and why; archon data set changes one opt-in's choice. Calling durable data ephemeral needs --confirm-destroy <host>, typed by a person.

Source: src/archon/optin/data.ts

HOME_RULEconst
const HOME_RULE: "Home directories are not kept across a reinstall: keep data in a share, a bucket, or a database."

Home directories on servers are ephemeral by rule (spec 044).

OFF_HOSTconst
const OFF_HOST: "no off-host copy yet: the destination is not chosen (a later spec adds it)"

Off-host copies are not built yet: a later spec adds the destination (a NAS).

DATA_DIRSconst
const DATA_DIRS: { pg: string; s3: string; smb: string; }

Where each opt-in keeps its data, as the host can see it without root.

dataOnDiskfunction
function dataOnDisk(dirs?: { pg: string; s3: string; smb: string; }): Promise<string[]>

The opt-ins whose data directory holds data on this host (Article 23's fail-safe: data with no recorded choice counts as durable). PostgreSQL: a cluster directory under /var/lib/postgresql/<version>/. S3: /srv/s3 is private to the container's account, so its link count says whether RustFS made anything in it (an empty directory has two). SMB: anything in the shared folder. A directory that cannot be read counts as holding data.

dataShowfunction
function dataShow(hostName: string, json: boolean): Promise<number>

archon data: shows whether a host is durable or ephemeral and why (as JSON with json). Returns 1 while any opt-in's data is still unchosen, else 0.

dataSetfunction
function dataSet(hostName: string, name: string, data: DataClass, confirm: unknown): Promise<number>

archon data set: records one opt-in's data class in the host's state, re-renders its files, and notifies. Calling durable data ephemeral needs confirm (--confirm-destroy <host>). Returns 1 when the apply failed.
