graph

Spec 090: the estate graph, built from a Snapshot into SQLite (node:sqlite, the same on Bun and Node) with the schema in schema.ts.

  • People come only from the source of truth: the first connected source in fleet.ts's order (HR systems, then identity providers). Every other source links to them.
  • Accounts and repositories are nodes, labeled user_account and code_repository. An account is linked to its person (has_account) by work email, or by a manual link in links.ts.
  • Machines are fixed assets, deduplicated by serial number, then hostname (links.ts overrides); a device with no serial number (an EDR's) joins the machine with its hostname. Each property records the source it came from (Stolos's own, then the probe, then MDMs, then EDRs: SOURCE_RANK), and each source's record is linked by observed_as.
  • History: first-seen and last-seen times come from Git. When a source could not read something (an observation), its earlier nodes are kept, marked stale, rather than dropped.

Source: src/archon/estate/graph.ts

A machine's key: links.ts first, then its serial number, then its hostname. A device with no serial number (an EDR that does not report one) joins the machine another source knows by the same hostname and a serial number, when serialByHostname names exactly one.

serialKeysByHostnamefunction
function serialKeysByHostname(devices: Device[]): Map<string, string | null>

Each hostname's serial-number key, from the devices that report both; null when two machines share a hostname (a default name like "macbook-pro"), so a device with only that hostname is not joined to either.

SOURCE_RANKconst
const SOURCE_RANK: Record<string, number>

Whose word wins for a machine's property when sources disagree (lower first): Stolos's own managed hosts, then its probe (adopted machines), then SNMP, then MDMs and directories (they enforce encryption and know the owner), then EDRs. A source not listed comes last.
