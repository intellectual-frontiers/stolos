probe

archon doctor's building blocks (spec 026): one HTTP(S) probe with curl's own timings, what a curl failure means, and parsers for the output of Ubuntu's network tools. Pure where it can be, so it is tested without a network.

Source: src/archon/doctor/probe.ts

Probeinterface
interface Probe

The result of one curl probe of a URL.

MemberTypeWhat it is
urlstringThe URL probed.
okbooleanAny HTTP answer (even 404) means the path works; ok is false only without one.
httpnumberThe HTTP status code; 0 without an answer.
curlExitnumbercurl's exit code (0 on success; see explainCurl).
ip?stringThe address curl connected to.
dns?numberSeconds, cumulative as curl reports them.
connect?numberSeconds until the TCP connection was made.
tls?numberSeconds until the TLS handshake finished.
total?numberSeconds for the whole request.
effective?stringThe final URL, after any redirects followed.
error?stringcurl's error message, without its curl: (N) prefix.

function probe(url: string, o?: { ipv4?: boolean | undefined; get?: boolean | undefined; follow?: boolean | undefined; timeout?: number | undefined; }): Promise<Probe>

Probe a URL with curl: HEAD by default, following redirects when asked.

parseProbefunction
function parseProbe(url: string, code: number, stdout: string, stderr: string): Probe

Build a Probe from curl's -w output (status, IP, timings, final URL), exit code and stderr.

What a curl exit code means for this machine's network, and where to look.
