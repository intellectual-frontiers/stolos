exports

Spec 092: the exports API. One function, buildExports, turns what Stolos knows into a document in a standard format, as bytes with a file name and a media type, so delivery code (OTLP sending, files, email, schedules) needs to know nothing about the formats.

KindFormatNeeds
ocsf-jsonlOCSF 1.9.0 events, JSON Linesestate and/or compliance view
otlp-jsonOTLP/HTTP JSON logs request (the OCSF events)estate and/or compliance view
cyclonedx-attestationCycloneDX 1.6 attestation (CDXA)compliance view (bundle optional)
intoto-statementin-toto Statement v1 for an evidence bundlebundle
oscal-component-definition, oscal-ssp, oscal-assessment-results, oscal-poamOSCAL 1.2.3 (spec 071)compliance view with the SCF catalog

Every document is a function of its input: the same input gives the same bytes (the time is part of the input).

Source: src/archon/export/exports.ts

ExportInputinterface
interface ExportInput

What an export is made from; each kind uses what it needs and says what is missing.

MemberTypeWhat it is
fleet{ id: string; title: string; repo: string; }The fleet.
nowDateThe time the documents are stamped with.
estate?EstateThe estate graph (people, accounts, machines, other nodes).
view?ComplianceViewThe compliance view (every control with its evidence).
catalog?ScfCatalogThe SCF catalog (framework mappings in findings; needed by OSCAL).
machines?{ name: string; kind: string; os?: string | undefined; }[]The fleet's machines, for the OSCAL SSP's inventory.
nistTitles?Record<string, string>SP 800-53 titles by OSCAL id (when NIST's catalog is on this PC).
bundle?BundleInfoA spec 072 evidence bundle.
signer?stringThe fleet signer to name in an attestation (default: the bundle's signer).
entityEvents?booleanOTLP: also send inventory as OpenTelemetry entity events (Development status; default off).
