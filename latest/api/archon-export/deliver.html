deliver

Delivery of exports (spec 092, part B): where a job's documents go, by the owner's rule.

  1. The fleet's OpenTelemetry collector (telemetry.collector in fleets/<id>/fleet.ts), over OTLP/HTTP, when one is configured and the job does not say otlp: false. A document that already is OTLP JSON goes to its own signal (/v1/logs, /v1/traces, /v1/metrics); any other is one log record whose body is the document, with its name, type, and SHA-256 as attributes.
  2. Otherwise a file in this PC's state directory, exports/<job>/<time>/<file> (also when the collector does not answer).
  3. A file can then be emailed (email in the job): send-only, through the fleet's mail setup (spec 027) or the job's own send-only credential, each recipient getting a copy encrypted to their own certificate (smime.ts). A job with recipients always keeps the file too.

Every run writes exports/<job>/last-run.json (what was made, where it went, what failed), which never holds a secret: errors are redacted with the credential in use.

The document formats themselves are produced elsewhere, each behind an ExportSource; this module only needs ExportDocument.

Source: src/archon/export/deliver.ts
