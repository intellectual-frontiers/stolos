catalog

040-opt-in: the catalog of opt-in containers. Each runs under Podman, from a Quadlet file (Podman's own systemd integration), on every server and masked until an operator turns it on. Images are pinned by digest (Article 12); a new version is a change to this file, through the spec loop.

Source: src/archon/containers/catalog.ts

ContainerDefinterface
interface ContainerDef

One container Archon can run as an opt-in (Podman, through a systemd quadlet).

MemberTypeWhat it is
namestringThe opt-in's name: its switch, archon-<name>.service, archon-<name> container.
titlestringWhat it is, in a few words, for people.
spec`${number}-${string}`The spec that describes it.
imagestringregistry/repository:tag@sha256:digest
uidnumberThe UID and GID the image runs as (data directories are owned by it).
ports{ host: number; container: number; route: string; description: string; }[]Published on 127.0.0.1 only: Traefik is the way in.
volumes{ host: string; container: string; }[]Host directories mounted into the container.
environmentRecord<string, string>Plain settings (never secrets).
secretsstringRoot-only file of generated secrets, written before the container first starts.
healthstringAnswers 200 when the container is ready (on 127.0.0.1).
S3const
const S3: ContainerDef

RustFS, the S3 server (spec 041): Apache-2.0, single node, its own console.

OTEL_UIconst
const OTEL_UI: ContainerDef

OpenObserve, the telemetry web UI (spec 050): logs, metrics, and traces in one place, OTLP in, a single node on local disk. AGPL-3.0 (fine for running it internally). Its own phone-home is off.
