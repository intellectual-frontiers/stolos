apply

archon apply: converge a host to its plan (Article XI). Idempotent: a run right after a successful run reports zero changes. Never removes anything (Article IX).

Source: src/archon/apply/apply.ts

ApplyOptionsinterface
interface ApplyOptions

What archon apply does.

MemberTypeWhat it is
checkbooleanOnly report what would change; change nothing.
root?stringAlternate root for files (testing). Skips packages, accounts, units, actions.
only?("accounts" | "containers" | "databases" | "dotfiles" | "files" | "packages" | "units")[]Run only these phases (default: all). A second pass after tools sync needs only dotfiles.
ApplyResultinterface
interface ApplyResult

What an apply did.

MemberTypeWhat it is
hoststringThe host's name.
checkbooleanWhether it was a check (nothing changed).
changesstring[]Every change made (or, in a check, that would be made), one line each.
skippedstring[]Steps left for a later run (for example a file whose owner does not exist yet).
failedbooleanWhether any step failed.
applyfunction
function apply(host: HostDef, opts: ApplyOptions): Promise<ApplyResult>

archon apply: converge the host to its plan. Must run as root unless check or root is set. A real run also records provenance (spec 014), restarts Archon's daemons when the code changed, commits /etc with etckeeper (spec 033), settles the install record after a success (spec 009), and, for a full apply, reports a change of state (spec 025).

archonDaemonsfunction
function archonDaemons(units: UnitDef[]): string[]

Archon's long-running services: managed units that run archon and are not oneshot.

restartArchonDaemonsfunction
function restartArchonDaemons(plan: HostPlan): Promise<string[]>

Restart Archon's own daemons when the checkout's code changed since they started (the checkout's HEAD, remembered in /var/lib/archon/status/daemons-head). A pull alone does not restart a running process, so without this the welcome page kept serving the code it started with.

etckeeperCommitfunction
function etckeeperCommit(changes: string[]): Promise<boolean>

Spec 033: commit /etc's changes as archon's, so etckeeper's history tells an archon apply from apt, unattended-upgrades, and a person.

settleInstallRecordfunction
function settleInstallRecord(hostName: string, root?: string): Promise<boolean>

The install record at "ok": false becomes ok once an apply succeeds; its problems are kept as resolved.

switchOnfunction
function switchOn(host: string, name: string, root?: string): Promise<boolean>

An operator's switch (spec 037): the opt-in record says {"enabled": true} (spec 048).
