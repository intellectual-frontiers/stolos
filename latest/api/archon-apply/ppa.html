ppa

Maintainers' PPAs (spec 010, Article 5). Ubuntu's own tool adds them: add-apt-repository fetches the PPA's signing key from Launchpad over HTTPS and writes a deb822 source with the key inline. Archon first checks that the PPA has builds for this release, so a PPA can never break apt.

Source: src/archon/apply/ppa.ts

function ppaSourcePath(ppa: string, codename: string): string

"git-core/ppa" -> the source file add-apt-repository writes.

The URL of a PPA's signed Release file (InRelease) for a codename on Launchpad's content host.

ppaHasReleasefunction
function ppaHasRelease(ppa: string, codename: string, o?: { ipv4Only?: boolean | undefined; retries?: boolean | undefined; }): Promise<{ answer: "no" | "unreachable" | "yes"; reason?: string | undefined; }>

Has the PPA published builds for this Ubuntu release? Asked with curl (IPv4 only on an IPv4-only network, spec 009), retried with the same backoff as apt (about 10 s, 30 s, 60 s). "unreachable", with curl's reason, after that.

Is the PPA already a source? Found by its URL, whatever the file is called.

function addPpa(ppa: string): Promise<{ ok: boolean; output: string; }>

Adds a PPA with add-apt-repository (non-interactive, without running apt update). Returns whether it succeeded and the tool's trimmed output.
