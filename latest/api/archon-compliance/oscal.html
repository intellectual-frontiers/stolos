oscal

Spec 071: the fleet's compliance in OSCAL, NIST's machine-readable format, so an assessor's or an agency's tools read it without retyping. Four documents, all to NIST SP 800-53 Rev 5 (the controls FedRAMP and most federal frameworks use), each control reached through SCF's own mappings:

  • a component definition: Stolos, and each source of evidence, with the controls each reaches;
  • a system security plan (SSP): this fleet, its machines, and how each control is implemented, importing NIST's moderate baseline;
  • assessment results: every observation Stolos made, and a finding per control (satisfied or not);

  • a plan of action and milestones (POA&M): each failing check, open, and each accepted risk, as a deviation approved until its date; and (spec

    1. each open risk in the fleet's risk register, with its SP 800-30 likelihood, impact, and level; and (spec 088) each open vulnerability a scanner's connector reported, with its CVE, severity, and asset.

UUIDs are UUIDv5 of what they name, so the same fleet exported twice names the same things the same way, and a diff shows only what changed.

Source: src/archon/compliance/oscal.ts

function uuidFor(...name: string[]): Promise<string>

A UUIDv5 (SHA-1, RFC 9562; kernel uuid.uuidV5) of a name in Stolos's namespace, its parts joined by NUL.

function oscal80053(id: string): string | undefined

An SP 800-53 id as SCF writes it (SC-28(01)) in OSCAL's form (sc-28.1), or undefined.

allEvidencefunction
function allEvidence(view: ComplianceView): Evidence[]

Every piece of evidence once (one can support several SCF controls). Two results of the same check on the same subject (rare, but possible) get distinct keys (#2, #3, in order), so their UUIDs never collide.
