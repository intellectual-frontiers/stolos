workflow

Spec 074: the workflow the engine writes into a fleet repository (.github/workflows/compliance-impact.yml), so that every pull request gets one comment naming the SCF controls its change affects, with their framework requirements, and fails its check when the fleet's gate (compliance.gate in fleet.ts) blocks it.

stolos fleet init writes it into a new repository (with the other scaffold files) and stolos fleet upgrade writes it again whenever the text differs from the one the upgrading engine writes (as it does for the bootstrap scripts), in the same signed commit as the new pin.

What it relies on, and nothing else: GitHub's own GITHUB_TOKEN, limited to contents: read and pull-requests: write, given only to the step that posts the comment; actions/checkout (without keeping its credentials) and oven-sh/setup-bun, each pinned to a commit. The comment holds control ids, host names, ports, networks, and the words of each change: never a secret.

Source: src/archon/compliance/workflow.ts
