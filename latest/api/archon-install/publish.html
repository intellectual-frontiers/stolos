publish

Specs 004 and 045: what stolos host add and boot retire change in the checkout is built, committed, and pushed by the same command (pushing to main is approval, Article 9). Only the paths the change touched are staged, with what stolos build renders from them (.mcp.json, the agent's permissions, the man pages); anything else in the working tree is left alone.

Source: src/archon/install/publish.ts

function publishChange(paths: string[], message: string, o?: { repo?: string | undefined; build?: boolean | undefined; identity?: { name: string; email: string; } | undefined; }): Promise<boolean>

Build, then commit paths (and the rendered files) with message, and push to the checkout's upstream, retrying a push that lost a race by rebasing. Returns whether the change is on GitHub.
