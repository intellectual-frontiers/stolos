paths

Well-known locations (spec 046-engine-instance). Two roots:

  • the engine: this repository, as a checkout or as the package a fleet repository installs (node_modules/@intellectual-frontiers/stolos, spec 096); its root is three folders above this module either way;
  • the instance: the repository that holds the fleets (fleets/<id>/), the one hosts check out at /srv/archon. One fleet of it is active per run.

The instance is ARCHON_REPO, else the nearest folder above the working directory that holds fleets/, else /srv/archon, else (in an engine checkout) its examples/. The fleet is ARCHON_FLEET (or --fleet), else /etc/archon/fleet (written at install), else this checkout's choice (stolos fleet use <id>, in .git/stolos/fleet, never committed), else the instance's only fleet.

A provider's PC (spec 082) works for many clients, each in its own checkout: --client <id> (ARCHON_CLIENT) points ARCHON_REPO and ARCHON_FLEET at that client's checkout and fleet, and this PC's per-user folders (state, secrets, the key store) move under stolos/clients/<id>/, so no two clients ever share one. The catalogs (public reference data) and the boot cache stay shared.

Source: src/archon/core/paths.ts

hostRootfunction
function hostRoot(): string

The host's root: ARCHON_ROOT=<folder> (tests, and the sandbox) stands in for the host's /. Every fixed path the engine reads or writes on a host (/etc/archon, /var/lib/archon, /var/lib/archon-keys, /var/log/archon, /opt/tools, /usr/local/bin, /srv/archon, etckeeper) resolves under it through onHost, and the run is root's (asRoot), so a test exercises root's side as an ordinary account, with stand-ins for the programs on PATH. Unset (production), every path is exactly the one named and asRoot is proc.isRoot(). Read on every call, so a test may set it in its own process. What a host is given to write (a rendered file's path, a unit's EnvironmentFile) always names the real path: only reading and writing move.
