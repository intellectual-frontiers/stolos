releases

Spec 099: the newest Stolos release, as stolos update, the Stolos Console and the Archon Console show it. One git ls-remote --tags of the engine's repository (a release is its tag stolos-v<version>, specs 096, 114-release-record), kept for an hour in a small cache file so a console page never waits on GitHub twice in a row. Unreachable: undefined, and the pages say nothing rather than something wrong.

Source: src/archon/fleet/releases.ts

RELEASE_CACHE_MSconst
const RELEASE_CACHE_MS: number

How long a lookup is kept.

newestTagfunction
function newestTag(lsRemote: string): string | undefined

The newest stolos-vX.Y.Z tag in git ls-remote --tags output; no other tag is a release.

isNewerfunction
function isNewer(newest: string | undefined, current: string | undefined): boolean

Whether newest is a newer release than current (both stolos-vX.Y.Z; false when either is not).

newestReleasefunction
function newestRelease(repo: string, o: { cacheFile: string; maxAgeMs?: number | undefined; now?: number | undefined; }): Promise<string | undefined>

The newest release of repo (owner/name on GitHub): from the cache when it is fresher than maxAgeMs, else asked now (and cached). Undefined when GitHub cannot be reached.
