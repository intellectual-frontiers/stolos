upgrade

stolos fleet upgrade <tag> (spec 046-engine-instance, Articles 9, 12, 24; spec 096 FR-006): move a fleet repository to another version of the engine, safely. A version of the engine is its tag v<version>: there is no GitHub release, and a fleet depends on the engine by Git.

Why each step exists (the fleet-repository guide, ./mod.ts, says it at length):

  1. The tag must be a version tag, and only forward unless --downgrade: going back to an older engine is a decision, not an accident.
  2. package.json's dependency on the engine is moved to that tag ("@intellectual-frontiers/stolos": "github:intellectual-frontiers/stolos#v<version>"), and bun install pins the commit the tag names, and its integrity, in bun.lock. The installed package must say it is that version: a typo, or a tag that is not that version, is refused and everything is put back. Hosts run bun install --frozen-lockfile: an engine that differs from the lock is refused, and a tag moved later changes nothing, since the lock holds the commit. That is what makes your signature cover the engine's bytes.
  3. Every fleet in the repository is validated with the new engine before anything is committed.
  4. The files are committed together and signed (git commit -S): hosts apply only a signed tip of main. Pushing it is the approval.

Source: src/archon/fleet/upgrade.ts
