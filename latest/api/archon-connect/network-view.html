network-view

Spec 110-network-assets: the network as the fleet sees it, from the connectors' last observations and the fleet's own records: the devices (adopted or only discovered), the clients (matched to the fleet's machines by MAC, or unmanaged), the VLANs and Wi-Fi networks, the edges the official API gives (uplink, connected-to, member-of, advertises), what it does not give (the gaps), and the counts by class. It is one pure function over data, so the console, stolos fleet status and the tests draw the same view.

Source: src/archon/connect/network-view.ts

MachineKeyinterface
interface MachineKey

A machine of the fleet, as far as the network cares: its name and how a client may be matched to it.

MemberTypeWhat it is
namestringIts name in the fleet.
macs?readonly string[]Its MAC addresses, where it records them (a check-in, a host's registration).
address?stringIts address, the fallback where it records no MAC.

tostringThe id of where it ends.

A client matched to a machine of the fleet.

MemberTypeWhat it is

NetworkViewinterface
interface NetworkView

The Network page's data: everything the observations and the records say, in one place.

MemberTypeWhat it is
connectors{ id: string; account: string; at: string; }[]The router-kind connectors that were observed, each with the account and when.
devicesDeviceRow[]Every device the controller reports.
assetsAssetStatus[]The assets against the observations (present, gone, unread).
discoveredObservedDevice[]Devices the controller reports that no asset records: discovered via the integration.
goneAssetStatus[]The assets that are gone from the integration.
clients{ client: ObservedClient; match?: ClientMatch | undefined; uplinkName?: string | undefined; }[]Every client, with the machine it matched when it did.
unmanagedObservedClient[]The clients no machine of the fleet matches.
matchesMap<string, ClientMatch>The machines a client matched, by machine name.
vlansObservedVlan[]The networks (VLANs).
ssidsObservedSsid[]The Wi-Fi networks.
edgesNetworkEdge[]The edges the API gave.
gapsstring[]What the observations could not read, and what the API does not give.
counts{ class: DeviceClass; adopted: number; discovered: number; }[]How many devices of each class the fleet has adopted.
matchClientsfunction
function matchClients(clients: readonly ObservedClient[], machines: readonly MachineKey[], deviceName?: (id: string) => string | undefined): { matches: Map<string, ClientMatch>; unmanaged: ObservedClient[]; }

Match clients to machines: by MAC first, then (said so) by address; each machine and each client at most once.

The view of the network: the observations of the router connectors, the fleet's assets, and the machines clients may match.

networkFactsForfunction
function networkFactsFor(view: NetworkView): Map<string, NetworkFacts>

What a rule over network facts may look at for each machine of the fleet (spec 110-network-assets FR-010): a network asset has its class, facets, uplink (by name), the Wi-Fi networks it broadcasts and the VLANs they carry; a machine a client matches has the name of the device it is connected through.
