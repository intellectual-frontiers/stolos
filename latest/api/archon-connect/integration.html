integration

Spec 109-integrations-api: the integration layer, an algebra of kinds and capabilities. An integration is an account's API read through one typed interface: it declares its kind (stolos:ApiKind: a router, a DNS provider, an email provider) and the capabilities of that kind it offers (stolos:ApiCapability: a router's clients, devices, networks and VLANs, ports, firewall rules; a DNS provider's zones and records; an email provider's domains, sending and routing), and each capability reads typed entities (Results) that join the estate graph through a connector's observation (integration-connector.ts).

The point is what the compiler refuses. A function that needs a capability takes Has of the kind and the capability, so an integration that does not offer it, or one of another kind, is a compile error at the call; and defineIntegration demands, for every capability of its kind that it does not offer, the reason it does not (notOffered), so a capability is either read or explained and never forgotten.

Source: src/archon/connect/integration.ts

function defineIntegration<K extends Kind, const C extends CapabilityOf<K>>(def: IntegrationDef<K, C>): Integration<K, C>

Make an integration. The offered capabilities are the keys of read; notOffered must hold exactly the others, which the compiler checks, and which this function checks again (a JavaScript caller, a stale file).

readAllfunction
function readAll(i: AnyIntegration, ctx: ReadContext, gaps: string[]): Promise<Reading[]>

Every capability an integration offers, read in turn: its readings, and a gap (in gaps) for each capability it does not offer (with its reason) and for each it offers that the account would not let it read (a denied or absent endpoint). Any other failure (the network, a certificate, a body that is not JSON) is thrown: the account was not reached.

memoGetsfunction
function memoGets(t: Transport): Transport

A transport that answers a GET it has answered before, within one observation, from the first answer, and sends everything else on. Only an answer that will not change on a retry is kept (not a 429 or a 5xx), so the backoff above it still works. Two readers of one account (a connector and an integration) then send each request once.
