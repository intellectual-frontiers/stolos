state-command

archon state (spec 048): what this machine recorded about itself (its install, its latest verify, the operators' switches) and whether it holds durable data, from its own archon.sql. Fleet status asks each server for this over MCP; nothing is pushed.

Source: src/archon/state/state-command.ts

HostStateinterface
interface HostState

What a machine recorded about itself (archon state; MCP archon_state).

MemberTypeWhat it is
hoststringIts name.
install?{ at: string; body: Record<string, unknown>; }Its install record.
verify?RecordedVerifyIts latest verify.
inventory?InventorySpec 051: what the machine is, as it reports itself.
optInsRecord<string, unknown>Opt-ins and their records.
data{ class: string; reasons: string[]; }Its data class (Article 23).
reported?{ machineInfo?: Record<string, string> | undefined; tags: TagBody[]; }Spec 112-machine-reported-tags FR-005, FR-007: what this machine says about itself: its /etc/machine-info (as bounded text) and the rows of its own tags table. The PC reads them as untrusted claims (its inventory above carries the firmware facts).
compat?{ engine: string; seams: Record<string, { current: string; minimum: string; }>; }Spec 115-compatibility FR-005: the engine this machine runs and the version of each seam it has (current, and minimum, the oldest PC it reads). The PC compares them with its own contract; the machine reads nothing for it but constants.
applied?{ commit: string; subject: string; at: string; }Spec 066: the commit this host applies now (its checkout's HEAD).
sync?SyncStatusSpec 066: what its last pull did (and why it could not, when it could not).
atstringWhen this was read.
