SQL over your infrastructure

#SQL over your infrastructure

Every host can answer questions about itself, its files, its databases, and its buckets in SQL (spec 042):

ToolAsksWhere
osqueryithe machine: processes, ports, users, packages, units, files, about 280 tablesevery host
duckdbfiles (CSV, JSON, Parquet), S3 buckets, PostgreSQL, SQLiteevery host
jcturns command output (ps, df, ss, dig, systemctl...) into JSON, for DuckDBevery host
sqlite3SQLite filesevery host
steampipelive APIs: GitHub, clouds, DNS, certificates, with your own credentialsworkstations

#The machine (osquery)

osqueryi is an interactive SQL shell over the machine. Run it with sudo to see everything (without it, some tables show only your own processes and files):

.tables lists the tables, .schema processes shows one, and .exit leaves. One query from the command line: sudo osqueryi --json "SELECT * FROM uptime;".

osquery's daemon (osqueryd) runs on every host as infrastructure. It listens on no port: it runs Archon's scheduled queries (ports, logins, users, sudoers, SSH keys, packages, kernel modules, failed units) and writes what changed to /var/log/osquery/osqueryd.results.log (rotated), so the machine's recent history is there to read:

#APIs (Steampipe, on your workstation)

Steampipe asks live APIs in SQL with your own credentials, so it runs on workstations (secrets stay off servers). Each source is a plugin:

The first run downloads Steampipe's own PostgreSQL and the plugins into ~/.steampipe. The GitHub plugin uses GITHUB_TOKEN (or gh auth token).

See also man archon-sql, osqueryi --help, duckdb --help, jc --help.

#Modules

capturearchon capture (spec 014, 048): read this host's actual state and compare it with the plan (drift).
inventorySpec 051: what this machine is, as it reports itself: make, model, serial, CPUs, memory, disks, and network cards, from its firmware tables, /proc, and /sys.
querySpec 048-observe-by-query (Article 17): archon query answers one SELECT about this machine through osquery, including Archon's own tables (archon_install, archon_verify, archon_prov, archon_optin,…
state-commandarchon state (spec 048): what this machine recorded about itself (its install, its latest verify, the operators' switches) and whether it holds durable data, from its own archon.sql.
storeSpec 048-observe-by-query (Article 25): what this machine recorded about itself (its install, its latest verify, what each run did, the operators' switches) stays on the machine, never in Git.
verifyarchon verify (Article 15, spec 014): run every verification command in the host's plan and report each result.
