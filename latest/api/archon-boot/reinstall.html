reinstall

bun run stolos boot reinstall <host> (spec 004): one command from the boot machine re-installs a running host, with no one at its console:

  1. the boot server must be running (it serves the install);
  2. (spec 048: the host keeps its own records; nothing is pushed);
  3. the host is armed for one install;
  4. over SSH, archon reboot --netboot boots it from the network once;
  5. this PC trusts the host's SSH host keys, which the install brings back. A host that cannot be reached is armed anyway, with what to do at its console. Article 23 (spec 044): a durable host (asked over SSH with archon data), or one whose data class cannot be read, is reinstalled only with --confirm-destroy <host>, typed by a person.

Source: src/archon-boot/reinstall.ts

function parseData(raw: string | undefined): { class: string; reasons: string[]; } | undefined

What a host says of its data (archon data --json), or undefined when it cannot be read.

destroyRefusalfunction
function destroyRefusal(name: string, data: { class: string; reasons: string[]; } | undefined, confirm: string | undefined, agent?: string | undefined): string | undefined

Article 23: refuse to erase a durable host (or one whose class is unknown) unless a person repeated its name with --confirm-destroy. Returns the refusal, or undefined when it may go ahead.

recordedDatafunction
function recordedData(host: HostDef | undefined): Pick<HostData, "class" | "reasons"> | undefined

The class the repository's records give (no SSH): for arming a host that may not answer.

reinstallfunction
function reinstall(name: string | undefined, o: { port: number; confirmDestroy?: string | undefined; }): Promise<number>

bun run stolos boot reinstall <host>: re-install a running host over the network in the steps the module describes. port is the boot server's HTTP port and confirmDestroy is the repeated name a durable host needs. A host that cannot be asked needs it too. Returns the exit code (2 for an unknown host).
