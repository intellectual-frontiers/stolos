apt

apt with real progress (spec 018): APT::Status-Fd=2 makes apt report "pmstatus:<pkg>:<percent>:<text>" and "dlstatus:..." lines on stderr, which drive the progress bar; everything else goes to the run log. apt's warnings are translated into problems with a fix instead of being pasted raw.

Source: src/archon/apply/apt.ts

aptDepsconst
const aptDeps: { stream: (argv: readonly string[], opts: { readonly env?: Readonly<Record<string, string>> | undefined; readonly cwd?: string | undefined; readonly onLine: (line: string, from: "stderr" | "stdout") => void; }) => Promise<number>; sleep: (ms: number) => Promise<void>; }

apt's runner and the pause between retries, replaceable in tests (spec 009).

NETWORKconst
const NETWORK: RegExp

A network-shaped apt failure (spec 009): DNS, unreachable, timed out. On an IPv4-only network with a flaky upstream resolver these come and go; they are retried, then reported as a warning that the next reconcile clears.

NETWORK_BACKOFF_MSconst
const NETWORK_BACKOFF_MS: number[]

Backoff before each retry of a network-shaped failure (about 10 s, 30 s, 60 s).

ARCHIVE_UNREACHABLEconst
const ARCHIVE_UNREACHABLE: "could not reach the Ubuntu archive; the next reconcile tries again"

The warning shown when apt could not reach the Ubuntu archive for network reasons.

AptIssueinterface
interface AptIssue

One problem found in apt's output, worded for people, with a fix when there is one.

MemberTypeWhat it is
level"fail" | "warn"A warning (apt's W:) or a failure (E:, Err:).
messagestringWhat went wrong.
fix?stringWhat to run or check to fix it.
network?booleanDNS, unreachable, or timed out: retried, then a warning (spec 009).
classifyAptLinefunction
function classifyAptLine(line: string): AptIssue | undefined

Turn apt's W:/E: lines into one actionable issue per cause.

DpkgFailureinterface
interface DpkgFailure

A package dpkg failed to install or configure.

MemberTypeWhat it is
pkgstringThe package's name (without architecture).
reasonstringdpkg's reason, from the line after its error.
cause?stringThe script's last output before dpkg gave up: usually the real cause.
dpkgFailureParserfunction
function dpkgFailureParser(): { feed(line: string): void; error(pkg: string, reason: string): void; failures: DpkgFailure[]; }

Collect "dpkg: error processing package X (--configure):" and the reason on the following line, so a failure names the package instead of apt's "Sub-process /usr/bin/dpkg returned an error code (1)".

LOCKEDconst
const LOCKED: RegExp

Another apt or dpkg (Ubuntu's daily apt run, unattended-upgrades) holds a lock.

AptResultinterface
interface AptResult

How an apt run ended.

MemberTypeWhat it is
okbooleanWhether it succeeded (a network-only failure is not ok, but is only warned).
networkbooleanIt failed for network reasons only (warned, not failed).
aptUpdatefunction
function aptUpdate(p: Phase): Promise<AptResult>

apt-get update: waits for another apt holding a lock, and retries network-shaped failures with backoff (spec 009). A failure that stays network-shaped is a warning; anything else is a failure.

aptInstallfunction
function aptInstall(p: Phase, pkgs: string[]): Promise<AptResult>

Install packages. When a maintainer script fails (often a transient problem during a large first install, such as an initramfs rebuild triggered mid-run), finish pending setup with dpkg --configure -a and try once more; only a second failure is reported as one.
