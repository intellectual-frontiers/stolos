joining

Spec 107-pairing-and-query: how a machine came to be in the fleet. The ways are the ontology's (stolos:WayOfJoining): the controller PC is auto-adopted (spec 097: the fleet adopts it by itself, it needs no pairing and is observed by the local probe), a machine adopted through stolos pair is paired, one adopted by hand (a check-in code, host adopt) or a device read over SNMP is integrated, a server or workstation Stolos installs is managed, and a cloud account's machine is cloud. A machine only discovered has joined nowhere yet. Both consoles and the command line read the mark from here.

Source: src/archon/adopt/joining.ts

JoiningFactsinterface
interface JoiningFacts

What decides a machine's way of joining.

MemberTypeWhat it is
kindMachineKindThe machine's kind (the controller is an adopted machine whose role says so).
role?"controller"An adopted machine's role (controller: the fleet's own PC).
joined?"integrated" | "paired"What its declaration records (spec 107: written by stolos pair).

The way a machine joined, or undefined where it has not joined (discovered only).

The word for a way of joining, as the tables and the filter show it.

The badge of the controller: what its mark says in full.

CONTROLLER_NOTEconst

Why the controller needs no pairing, and cannot be released or removed from here (the console says it beside the disabled actions).
