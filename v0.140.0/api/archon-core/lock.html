lock

One archon run at a time per host (specs 012, 017), on IFC TypeScript's lock. The reconcile timer applies every 15 minutes; without this it could apply, or fetch, in the middle of someone's archon update or bootstrap. Children of a run that holds the lock (bootstrap and update hand-offs, reconcile's apply) inherit it through ARCHON_LOCK_HELD instead of waiting for their own parent. The lock file says who holds it: the command, and who started it (ARCHON_AGENT: the reconcile timer, an agent over MCP, a terminal), so a waiting run can say what it waits for.

Source: src/archon/core/lock.ts

holderCommandfunction
function holderCommand(args?: readonly string[], agent?: string | undefined): string

What the lock file says this run is: archon reconcile, the reconcile timer.

hostLockfunction
function hostLock(opts: { readonly wait: boolean; readonly onWait?: ((holder: Holder | undefined) => void) | undefined; }, path?: string): Promise<Held | undefined>

Take the host lock. Undefined when wait is false and another run holds it; onWait is called once, with the holder, when the lock is not free. Where the lock file cannot be made at all (not root, no /run), there is nothing to coordinate with, and a lock that releases nothing is given.
