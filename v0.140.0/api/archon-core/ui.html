ui

Calm output (Article XXII, spec 018): quiet on success, loud and actionable on problems, full detail always in the log. On IFC TypeScript's tty, stdio and fs; this is the one module of the engine that writes for a person to the terminal (the lint rule ifc/terminal-writers allows it alone).

✅ Packages 86 installed (1m12s) ⠸ Files [██████░░░░] 30/47 /etc/ssh/sshd_config.d/50-archon.conf

Terminal: spinner, progress bar, in-place redraw, colors, emoji. Pipe/timer/journald: plain final lines only. NO_COLOR disables color. Non-UTF-8 locale or ARCHON_PLAIN=1: ASCII marks ([ok] [warn] [FAIL]).

Source: src/archon/core/ui.ts

Leveltype
type Level = "ok" | "warn" | "fail" | "defer" | "skip";

How a phase ended: ok, with warnings, failed, deferred (a disruptive change left for later), or skipped.

ProblemLeveltype
type ProblemLevel = "warn" | "fail" | Extract<OutcomeLevel, "pending" | "action">;

Spec 052: the states, the same everywhere. "fail" and "warn" are problems; "pending" is something not set up yet, expected until someone does it (a token not pushed, a certificate not issued yet): shown with its next step, never a failure, never counted as a warning. Spec 099: "action" (⚡) is a step that is the operator's to take (send a change, back up, approve): nothing is wrong, so it is neither a warning nor an error. Spec 101-ladder FR-006: "pending" and "action" are the ontology's outcome levels (stolos:OutcomeLevel); "warn" and "fail" are the words a run's log and JSON carry for the levels "warning" and "failed".
