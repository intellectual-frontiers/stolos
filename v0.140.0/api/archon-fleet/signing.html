signing

Signing a commit with the person's daily key, and what is said about it (spec 105-calm-output FR-012, FR-013, FR-014): the line that names what is being signed, a wrong passphrase retried in place (three tries), and the engine upgrade that waits for its signature. The passphrase is asked once per command and kept only in its memory (spec 106-one-passphrase-speed): it goes from the person to the command's session and from there to OpenSSH, never to a file, a log or an argument.

Source: src/archon/fleet/signing.ts

commitSignedfunction
function commitSigned(repo: string, args: string[]): Promise<SignedCommit>

git commit, signed: the key's passphrase is asked once for the whole command and kept only in its memory (spec 106-one-passphrase-speed FR-001 to FR-003), whatever number of commits it signs. A wrong passphrase is said so ("That passphrase didn't unlock your daily key (2 left)") and tried again, up to three times in all; what was typed replaces what was kept only after it unlocked the key. The raw text goes to the run log, not the screen, and the passphrase to no log at all.
