    • archon/model/types.ts

The Archon model (spec 002): a fleet with one shared identity and one file per host. Capabilities contribute packages, files, units, and the rest to a host's plan. TypeScript types plus validate.ts are the whole validation story (Article 10); RDF is only an export.

Interfaces

I
AptRepoDef

A vendor's official apt repository (spec 010): its signing key is pinned in this repository and the source is written in deb822 form. Kept current by unattended-upgrades through site.

  • components: string
  • id: string
  • key: string

    ASCII-armored public key, pinned (Article 12).

  • site: string

    The repository's host, for unattended-upgrades' Origins-Pattern (site=...).

  • spec: SpecId
  • suites: string
  • uri: string
I
BackupDef

Backups (spec 016, Article 14): what to archive, where, and how many to keep.

  • keep: number
  • onCalendar: string
  • paths: string[]
  • target: string

    Directory the archives go to (default /var/backups/archon, Ubuntu's backup location).

I
CapabilityContext

What a capability is given: the host, its fleet, and the people with accounts on it.

  • fleet: FleetDef

    Its fleet.

  • host: HostDef

    The host being planned.

  • users: UserDef[]

    Every account on it (the admin, ops, and the host's users).

I
CheckDef

A verification the model declares (Article 15). "warn" checks report a warning with their fix and never count as a failure (installed.json stays ok).

  • code: string

    Spec 052: archon explain <code>. Exit 3 from the command means "not set up yet".

  • command: string

    Run without a shell (splitArgs); use sh -c '...' for pipes. Exit 0 means pass.

  • fix: string
  • level: "fail" | "warn"
  • name: string
  • spec: SpecId
I
Contribution
  • aptRepos: AptRepoDef[]
  • checks: CheckDef[]
  • derive: (plan: HostPlan) => FileDef[]

    Files computed from the whole plan (for example the firewall from all ports).

  • files: FileDef[]
  • notes: string[]
  • packages: PackageDef[]
  • ports: PortDef[]
  • routes: WebRoute[]

    Services published through the proxy (spec 032).

  • spec: SpecId
  • tools: ToolDef[]
  • units: UnitDef[]
I
DiskDef

Disk layout handed to Ubuntu's installer (spec 004): Ubuntu's own guided layouts.

  • layout: "lvm" | "direct"

    Ubuntu's guided layouts; lvm is Ubuntu's default.

  • match: "largest" | `/dev/${string}`

    Device path, or "largest" for the largest disk.

I
FileDef
  • content: string
  • group: string
  • mode: string
  • onChange: Action[]
  • owner: string
  • path: string
  • postValidate: string[]
  • spec: SpecId
  • symlink: string
  • validate: string[]
I
FleetDef

The fleet: one identity shared by every host (spec 003), in fleets/<id>/fleet.ts of a fleet repository. archon fleet init <id> writes the first one from your GitHub account; edit it freely after, then archon build.

  • admin: { user: string; uid: number; github: GitHubIdentity; }

    The fleet's admin: one person, one account on every host (spec 003).

  • id: string

    The fleet's id: its folder, fleets/<id>/, and a DNS label (lowercase, digits, hyphens).

  • keyboard: string

    The console's keyboard layout, for example "us".

  • locale: string

    For example "en_US.UTF-8".

  • mail: { to: string; domain: string; tag?: string; relay?: string; }

    Outbound mail (spec 027) and notifications (spec 025). Every server relays its mail (Postfix) through Cloudflare Email Service, from <user>+<host>.<tag>@<domain> (only <domain> onboarded for Email Sending in Cloudflare); mail for local accounts (root, ops) and archon's own messages go to to. Without it, no mail leaves and archon notify is not configured.

  • mcp: { maxTier?: McpTier; keys?: string[]; }

    The agent layer (spec 030, Article 17): workstations reach each server as ops over SSH, forced to archon mcp --max-tier <maxTier>. Default: tier mutate, the admin's GitHub SSH keys. The destructive tier is never served.

  • network: Partial<NetworkDef>

    The fallback network facts (spec 009) for a host that is not on a site network (a workstation). A host on the site takes them from its network.

  • observability: Partial<ObservabilityDef>

    Local observability limits for every host and workstation (spec 021).

  • providers: Partial<ProvidersDef>

    DNS, mail, and ACME providers (spec 046); see ProvidersDef for the defaults.

  • repository: { slug: string; url: string; branch?: string; }

    The GitHub repository hosts converge to; branch defaults to main (tests use their own).

  • services: ServiceDef[]

    Service accounts for apps, the same on every server (spec 039): Linux system accounts named s-<app>, with fixed UIDs, no password, no shell. An app runs as its account and reaches PostgreSQL as the role of that name.

  • signers: SignerDef[]

    Who may approve changes (spec 047): loaded from fleets/<id>/signers.ts.

  • site: SiteDef

    The site's network as data (spec 028, Article 21): fleets/<fleet>/site.ts.

  • ssh: { passwordFrom?: string[]; }

    SSH (spec 007): networks (CIDR) from which passwords are accepted as well as keys. Default: the private ranges (your LAN and VLANs). [] means keys only.

  • telemetry: { collector?: string; name?: string; }

    A central OpenTelemetry collector (spec 024). Hosts and workstations look for one every 15 minutes, by unicast DNS only (Article 20): this address, else the name (default "otel.localdomain", a UniFi Local DNS record) on port 4318. Until one answers, everything stays local.

  • timezone: string

    An IANA time zone, for example "America/New_York".

  • title: string

    Its name, for people.

  • ubuntu: { release: "26.04"; codename: "resolute"; point?: string; }

    The Ubuntu release every host runs (point: a point release's image, when pinned).

  • web: WebFleetDef

    HTTPS on every server (spec 032): each answers as <host>.<domain> and its apps as <app>.<host>.<domain>, with one Let's Encrypt certificate per server (the name and its wildcard) through Cloudflare's DNS challenge. Each server keeps its own A records in Cloudflare (private addresses). Without it, servers still answer HTTPS with a self-signed certificate.

I
GitHubIdentity

A GitHub account as gh reports it (spec 003). Public data only.

  • email: string

    GitHub's anonymized commit address: <id>+<login>@users.noreply.github.com.

  • id: number

    GitHub's numeric account id (it never changes, unlike the login).

  • login: string

    The GitHub login.

  • name: string

    Profile name, or the login when the profile has none.

  • sshKeys: string[]

    Public SSH keys from https://github.com/<login>.keys.

I
GitHubSource
  • asset: (
    arch: "amd64",
    version: string
    ) => RegExp
  • repo: string
  • tagPrefix: string
I
GuestDef

An LXD instance on a host (spec 017).

  • cpus: number
  • data: DataClass

    Required (Article 23, spec 044): "durable" when the guest can hold data that exists nowhere else (backed up with lxc export and guarded), or "ephemeral" when losing it is harmless. There is no default.

  • image: string

    LXD image, for example "ubuntu:26.04".

  • kind: "container" | "vm"
  • memory: string

    For example "4GiB".

  • name: string
  • web: { port: number; https?: boolean; }

    Publish the guest's web port as <guest>.<host>.<domain> (spec 032).

I
HostDecisions

What operators decided for a host, in Git (spec 047): fleets/<id>/hosts/<host>/decisions.ts, written by archon decide. A decision here wins over the host's own record.

  • optIns: Record<string, OptInRecord>
I
HostDef

A host: one machine of the fleet, in fleets/<id>/hosts/<name>/host.ts. archon host add <name> --claim (or --mac-address) writes a server's; archon workstation add a workstation's. What it gets comes from its capabilities; what it is (its MAC, its SSH host keys) is in its registration.ts, from the machine itself (spec 051).

  • arch: "amd64"
  • backup: Partial<BackupDef>

    Overrides of the default backup policy (spec 016).

  • capabilities: Capability[]
  • desktop: boolean

    Workstations (spec 036): a graphical desktop, not WSL or a headless machine. VS Code is installed only here; set by archon workstation add.

  • disk: DiskDef

    Servers: the install disk (default: Ubuntu's LVM layout on the largest disk).

  • dnsName: string

    Its unicast DNS name, a UniFi Local DNS record (Article 20): "alpha.localdomain".

  • guests: GuestDef[]

    LXD containers and VMs (spec 017).

  • ip: string

    Its fixed address (a UniFi Fixed IP), inside its network (spec 028).

  • ipv6: boolean

    Per-host override of the network's IPv6 (spec 009).

  • kind: "server" | "workstation"

    "server" (default): an Ubuntu Server host Archon installs and converges. "workstation" (spec 020): Ubuntu on WSL (or a desktop) where Archon applies only the user-level parts: tools, dotfiles, the archon command.

  • mac: string

    Optional, and no longer written by archon: the NIC the host network-boots from (lowercase, colon-separated). Since spec 051 the MAC lives in registration.ts, given with --mac-address or reported by the machine; a mac here is still read. Without either, the host is recognized by a claim or its own Boot URI (/boot/<name>/bootx64.efi).

  • name: string

    Its name: a DNS label, unique in the fleet.

  • network: string

    The site network it lives on (spec 028), by name: "Servers". Its IPv6 follows that network.

  • observability: Partial<ObservabilityDef>

    Overrides of the fleet's local observability limits (spec 021).

  • optIn: Record<string, OptInRecord>

    Opt-in services and containers an operator turned on or off (spec 040): this machine's archon.sql<name>.json {enabled, by, at}. Read by loadHosts; never written in a host file. Absent means off.

  • outOfBand: { amt?: { address?: string; notes?: string; }; }
  • pg: { instances?: PgInstanceDef[]; }

    PostgreSQL instances this server keeps (spec 038).

  • pgState: PgState

    What operators recorded on this host (the host's own archon.sql (opt-in pg), spec 038): the clusters Archon created and which are published. Read by loadHosts; never written in a host file.

  • registration: HostRegistration

    Who it is, from fleets/<id>/hosts/<host>/registration.ts (spec 047): read by loadHosts.

  • spec: SpecId
  • switchPort: string

    The switch port it is cabled to: "flex-2.5g/3".

  • user: string

    Workstations: the existing account Archon sets up (default: the fleet admin's name).

  • users: UserDef[]

    Extra accounts beyond the fleet admin and ops.

  • web: { routes?: Array<Omit<WebRoute, "spec">>; }

    Services this server publishes through its proxy (spec 032).

I
HostRegistration

Who a host is, in Git (spec 047): fleets/<id>/hosts/<host>/registration.ts, written by archon host add. Public facts only: its SSH host public keys (operators' known_hosts is generated from them), its network card, and the fingerprint of its read-only deploy key.

  • added: string

    When it was registered (ISO date).

  • deployKey: string

    SHA256:... of its deploy key, when it has one.

  • mac: string

    The network card it is recognized by when it network-boots (spec 051).

  • macSource: "operator" | "installed"

    Where that MAC came from (spec 051): "operator", given with --mac-address; "installed", reported by the machine itself when it installed (or was bootstrapped). Only a machine that installed as this host is reinstalled without the blank-disk guard.

  • sshHostKeys: string[]

    "ssh-ed25519 AAAA...", "ecdsa-sha2-nistp256 AAAA...", "ssh-rsa AAAA..." (no comments).

I
NetworkDef

The network a host lives on (spec 009).

  • ipv6: boolean

    Does this network route IPv6? false (an IPv4-only LAN): apt resolves and connects over IPv4 only, and retries transient failures.

I
ObservabilityDef

Local observability (spec 021). Every store is ephemeral: each has an age and a size limit, and gives way first when the disk runs low. The limits are upper bounds, not promises.

  • logsMaxSize: string

    ...in at most this much space (journald also keeps 15% of the disk free).

  • logsRetention: string

    journald: kept up to this long (journald syntax, for example "3month")...

  • metricsDays: number

    PCP metric archives: kept up to this many days...

  • metricsMaxSize: string

    ...and pruned, oldest first, beyond this size (for example "2G").

  • minFreePercent: number

    Below this much free disk (percent), metric archives are pruned regardless of age.

  • tracesDays: number

    Archon's own traces, metrics, and logs (OTLP files): kept up to this many days, 64 MB at most.

I
OptInRecord
  • at: string
  • by: string
  • data: DataClass

    For an opt-in that holds end users' data: the operator's choice (spec 044).

  • enabled: boolean
I
PackageDef
  • debconf: string[]

    Answers to the package's own install questions, as debconf-set-selections lines ("postfix postfix/main_mailer_type select No configuration"), set before it is installed: Ubuntu's way to install a package unattended.

  • name: string
  • ppa: string

    The upstream maintainers' Launchpad PPA ("owner/name") that carries newer builds (Article 5). Added with add-apt-repository, kept current by unattended-upgrades; without builds for this release, Ubuntu's package stays.

  • repo: string

    A vendor's own apt repository (AptRepoDef.id) that carries this package.

  • source: "apt" | "snap"

    apt (default) or snap: both are native on Ubuntu (Article 2).

  • spec: SpecId
I
Persona

A persona's definition: what it means and what it brings (spec 012).

  • definition: string

    What it means, in one sentence.

  • features: { fish: boolean; tmux: boolean; devTools: boolean; }

    What it turns on.

  • groups: string[]

    Linux groups it adds.

  • id: PersonaId

    Its id.

  • implies: PersonaId[]

    Personas it includes (an operator is also a developer).

  • label: string

    Its name, for people.

I
PgDatabaseDef

A database in an instance and who may use it (spec 039). Every name is a Linux account (a person in the model, or a service account s-<app>) or

  • extensions: string[]

    Extensions Archon creates (as the superuser, for untrusted ones).

  • name: string
  • owner: string

    Owns the database and its public schema (creates tables).

  • read: string[]

    Read every table.

  • write: string[]

    Read and write every table (not create).

I
PgInstanceDef

A named PostgreSQL instance: one Debian cluster, <version>/<name> (spec 038).

  • databases: PgDatabaseDef[]
  • environment: string

    Shown in the psql prompt: production, staging, development... (default production).

  • name: string
  • port: number

    Fixed port (default: the first free from 5432, then kept).

  • protected: boolean

    psql turns AUTOCOMMIT off and warns in red (default true for production).

  • version: number

    Major version (default 18, Ubuntu's).

I
PgRecord

One instance as recorded on the host (the host's own archon.sql (opt-in pg)).

  • by: string
  • created: string

    ISO time and who: Archon owns only clusters it created (FR-003).

  • environment: string
  • port: number
  • protected: boolean
  • published: { at: string; by: string; localOnly?: boolean; }

    Published: reachable on the server's address over TLS (scram-sha-256). From anywhere the router lets through, unless localOnly (archon pg publish --local-only).

  • retired: number[]

    Older clusters kept, stopped, after an upgrade (removed with archon pg remove --version).

  • version: number
I
PgState

the host's own archon.sql (opt-in pg): the opt-in switch (spec 040) and the instances Archon made.

  • instances: Record<string, PgRecord>
I
PortDef
  • from: string[]

    Only from these networks (CIDR), for example the local networks; default: anywhere.

  • port: number
  • protocol: "tcp" | "udp"
  • spec: SpecId
I
ProvidersDef

The fleet's outside providers (spec 046), each a closed set the engine implements. Defaults: Cloudflare for DNS and mail, Let's Encrypt for ACME.

  • acme: "letsencrypt" | "letsencrypt-staging"

    Certificates (spec 032). "letsencrypt-staging" gives untrusted certificates with generous rate limits: for synthetic and test fleets.

  • dns: "cloudflare"

    DNS: each server's records and the ACME DNS challenge (spec 032).

  • mail: "cloudflare"

    Outbound mail: the SMTP relay (Cloudflare Email Service, spec 027).

I
ServiceDef

An app's own Linux account (spec 039).

  • description: string
  • name: string

    s-<app>: lowercase letters, digits, and dashes.

  • uid: number

    Fixed, so the account is the same on every server: 800 to 899.

I
SignerDef

Who may approve changes to a fleet (spec 047, Article 9): a host applies only a tip of main signed by one of these keys. Kept in fleets/<id>/signers.ts, written by archon signers.

  • added: string

    When it was added (ISO date).

  • key: string

    The public key: "ssh-ed25519 AAAA..." (or sk-ssh-ed25519@openssh.com).

  • name: string

    A short name, the principal in allowed_signers ("alice-daily").

  • role: "daily" | "recovery"

    daily: approves changes; recovery: kept offline, replaces a lost or stolen daily key.

I
ToolDef
  • bins: string[]
  • forPersona: PersonaId
  • github: GitHubSource
  • id: string
  • installer: string
  • name: string
  • package: string
  • ppa: string

    apt tools: the maintainers' PPA with newer builds (PackageDef.ppa).

  • repo: AptRepoDef

    apt tools: the vendor's own apt repository (PackageDef.repo).

  • restarts: string[]

    Services restarted after this tool is installed or upgraded (for example its own daemon).

  • serverOnly: true

    Installed on servers only (the HTTPS front door, spec 032).

  • source: "apt" | "snap" | "upstream-binary" | "self-updating"
  • spec: SpecId
  • unprivileged: true

    The tool refuses to run as root (Steampipe): its smoke test and its verify check run as nobody when archon runs as root.

  • verify: string
  • versionCommand: string
  • workstationOnly: true

    Installed on workstations only (the agent layer, spec 030), never on servers.

I
UnitDef
  • content: string
  • generated: boolean

    Made by a systemd generator (a Podman Quadlet container, spec 040): it cannot be enabled; its [Install] section starts it at boot unless masked. Turning it on is unmask and start.

  • managed: boolean
  • onCalendar: string
  • spec: SpecId
  • start: boolean
  • state: "enabled" | "disabled" | "masked" | "ignore"

    masked: stopped and masked, the package kept (spec 001: avahi-daemon).

  • switch: string

    An operator's switch (spec 037): the name of a record in this machine's archon.sql<switch>.json. When it says {"enabled": true} the unit is enabled and started; otherwise state applies (masked, for SMB).

  • unitName: string
  • verify: string
I
UserDef

A person's account on a host (spec 012): the fleet admin, or one of a host's extra users.

  • admin: boolean

    In the sudo group.

  • email: string

    Their address, for git and notifications.

  • fullName: string

    The person's name (GECOS).

  • name: string

    The Unix account name.

  • personas: PersonaId[]

    What they do here: their groups and tools follow.

  • spec: SpecId

    The spec that brought them.

  • sshKeys: string[]

    The public SSH keys that may log in as them.

  • uid: number

    A fixed UID, the same on every host (default: assigned by Ubuntu).

I
WebFleetDef

HTTPS for every server (spec 032): names under one domain, certificates from Let's Encrypt.

  • acmeEmail: string

    Let's Encrypt account address (default: fleet.mail.to).

  • domain: string

    The DNS zone suffix servers live under, for example "lab.example.net".

  • zone: string

    The Cloudflare zone that holds it (default: the last two labels, "example.net").

I
WebRoute

A service published through the server's proxy (spec 032) as <name>.<host>.<domain>, from the local networks only.

  • address: string

    The backend's address (default 127.0.0.1).

  • description: string
  • https: boolean

    The backend speaks HTTPS (certificate not checked; loopback or guests only).

  • name: string

    A DNS label: the app's subdomain.

  • port: number
  • spec: SpecId

Something a host gets (spec 002): a function from the host, its fleet, and its users to what it contributes to the host's plan (packages, files, units, ports, checks, tools). foundation() is every server's set; a host lists more in its capabilities.

Article 23 (spec 044): data that can come from end users is either durable (it exists nowhere else) or ephemeral (losing it is harmless).

Tiers an agent may be given over MCP (spec 030); never destructive.

T
PersonaId = "standard" | "developer" | "operator"

What a person does on a host (spec 012): "standard" (uses it), "developer" (builds on it), "operator" (runs it). A user's personas decide their groups and tools.
