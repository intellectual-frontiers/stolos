# 096: Mapping from Deno to Bun and IFC TypeScript

## Test helpers

- `tests/assert.ts` is **deleted**. Import the assertions from
  `@intellectual-frontiers/ifc-ts/runtime/test` (`assert`, `assertEquals`, `assertStringIncludes`,
  `assertThrows`, ...). Note `assertThrows(fn, Class?, includes?)`: pass `Error` (or `undefined`)
  as the second argument where the old helper took anything.
- `tests/fixtures.ts` keeps its names (`KEY`, `fleet`, `host`).
- `tests/sandbox.ts` keeps its names (`sandbox`, `Sandbox`, `fingerprint`). `Sandbox.run(script,
args, stdin?, extra?)` runs the script with the runtime of the test itself (`bun <script>` on
  Bun, `node <script>` on Node, through `proc.execPath()`), from a cleared environment, as before.

The working guide for converting each folder of the engine under [spec 096](spec.md). It says, for
each piece of the old ground, what replaces it. It is part of the spec folder, so it is reviewed
with the spec. When a folder is done, nothing in it names `Deno`, `npm:`, `jsr:` or a URL import,
`tsc -p tsconfig.json` reports no error for it, and `bun run lint` and `bun fmt --check` pass on
it.

IFC TypeScript 0.2.0 is the ground: `@intellectual-frontiers/ifc-ts`, installed from its release
tarball (SHA-256 `8775581c3aab18c60c451d11d6e33eb4c1bf931693fa996155ee68be37544147`). Its
source is commons' `commons/ts` (README, `kernel/mod.ts`, `runtime/mod.ts`, `runtime/test.ts`).

## Imports

- **IFC TypeScript** has four entry points; nothing deeper is exported:
  - `@intellectual-frontiers/ifc-ts/kernel`: pure code, named exports and namespaces
    (`args`, `assess`, `attest`, `cms`, `der`, `dsse`, `evidence`, `glob`, `grc`, `jobs`, `md5`,
    `ocsf`, `oscal`, `otel`, `otlp`, `palette`, `png`, `render`, `signals`, `testRecord`,
    `testReport`, `uuid`, `vt`, `width`);
  - `@intellectual-frontiers/ifc-ts/runtime`: the namespaces `compile`, `dns`, `fs`, `git`, `grc`,
    `http`, `jobs`, `lock`, `net`, `otel`, `path`, `proc`, `sign`, `stdio`, `tcp`, `terminal`,
    `tty`, `watch`, and `errors`, `serve`, `mapError`, `toError`;
  - `@intellectual-frontiers/ifc-ts/runtime/test`: `test`, `proves`, `reviewed` and the
    assertions (tests only);
  - `@intellectual-frontiers/ifc-ts/runtime/test-run`: `runTests` (`tools/test.ts` only).
    Write `import { fs, path, proc } from "@intellectual-frontiers/ifc-ts/runtime";`, and refer to
    `fs.readTextFile`, `proc.env.get`. Where a module has its own variable named `path`, alias the
    namespace (`path as paths`).
- **Inside `src/`**: relative imports with the `.ts` extension, as before
  (`allowImportingTsExtensions`; the release build rewrites them to `.js`).
- **The engine by its name**, from `examples/` and from a fleet repository:
  `@intellectual-frontiers/stolos/<path under src, without .ts>`:
  `import type { HostDef } from "@intellectual-frontiers/stolos/archon/model/types";`,
  `import { foundation } from "@intellectual-frontiers/stolos/archon/capabilities/mod";`. In this
  repository the name refers to the package itself (`package.json` `exports`: `"./*": "./src/*.ts"`),
  so `examples/` load the sources, on Bun and on Node, with no build. `@stolos/...` is gone.
- **`ajv`**: `import { Ajv } from "ajv";` and `import { Ajv2020 } from "ajv/dist/2020.js";` (named
  imports; both type-check under `nodenext` and run on Bun and Node).
- **`node:` builtins** are allowed (no lint rule refuses them), but use the IFC TypeScript wrapper
  where there is one. Kept as they are: `node:sqlite` (`DatabaseSync`, the same on Bun 1.4.4 and
  Node 26), `node:dgram` (TFTP: IFC TypeScript has no UDP), `node:crypto` where Web Crypto has no
  equivalent.

## The strict configuration

`tsconfig.json` is IFC TypeScript's: `strict`, `noUncheckedIndexedAccess`,
`exactOptionalPropertyTypes`, `noPropertyAccessFromIndexSignature`, `noUnusedLocals`,
`noUnusedParameters`, `noImplicitReturns`, `noImplicitOverride`, `erasableSyntaxOnly`,
`verbatimModuleSyntax`. Do not relax it; fix the code. The common fixes:

- **TS4111** (a property of an index signature read with a dot): `r["key"]`, or give the value a
  type with that property (a decoder, an interface).
- **TS2532, TS18048, TS2538** (`noUncheckedIndexedAccess`): `xs[0] ?? fallback`, destructuring with a
  default (`const [a = ""] = s.split(":")`), `for (const x of xs)` instead of an index, or a check.
- **TS2379, TS2375, TS2412** (`exactOptionalPropertyTypes`): leave an optional property out rather
  than set it to `undefined`: `...(x === undefined ? {} : { x })`; or declare it `x?: T | undefined`
  where `undefined` is a meaning.
- **TS1294** (`erasableSyntaxOnly`): no `enum`, `namespace` or parameter properties
  (`constructor(readonly name: string)` becomes a field and an assignment).
- **TS1484** (`verbatimModuleSyntax`): `import type` / `type` for what is only a type.

The linter (`bunfig.toml`) adds: explicit return types on exported functions and methods, no `any`,
no `!`, no floating promises, `===`, `switch` over a union ending in `default: return absurd(x)`,
`consistent-type-imports`, and IFC TypeScript's rules: `ifc/no-vendor-api` (no `Deno.*` or `Bun.*`;
only `console/pam.ts` is allowed), `ifc/no-registry-import` (no `npm:`, `jsr:`, `http:`, `https:` or
`bun:`; only `console/pam.ts` may import `bun:ffi`), `ifc/module-doc` (every file starts with a
`/** ... @module */` block), `ifc/terminal-writers` (no `console.*`, `process.stdout` or
`process.stderr` in `src/` outside `core/ui.ts`). A command prints its result through `ui`
(`ui.say`, phases and problems) or, for what a program reads (`--json`, a pipe), through
`stdio.stdout.write`.

## Tests

The conversion of each test file:

1. Rename `tests/<name>_test.ts` to `tests/<name>.test.ts` (and `examples/**/*_test.ts` the same way):
   `ifc test` runs `*.test.ts`.
2. Start the file with its `/** ... @module */` block (what it tests, and which spec).
3. Import from `@intellectual-frontiers/ifc-ts/runtime/test`, never `tests/assert.ts`; the engine
   relatively (`../src/archon/...`), or by its name where the test plays a fleet.
4. Each `Deno.test("NNN: title", fn)` becomes
   `proves(["NNN-slug FR-MMM", ...], "NNN: title", fn)`, naming the requirements of spec `NNN`
   (its folder name, a space, and the `FR` id as its `spec.md` lists it) that the test's assertions
   actually check. Read the spec's requirements and the test's body; name only what the test shows.
   The title keeps its `NNN:` prefix. A test can prove requirements of several specs.
5. A test that proves no particular requirement (a sanity check, a helper's own test) stays
   `test("title", fn)`: it runs and is recorded, and claims nothing.
6. `Deno.test({ name, fn, ignore: x })` becomes `proves([...], name, fn, { skip: x && "why" })`
   (`todo` for one that waits for work); `sanitizeOps`, `sanitizeResources` and `permissions` have
   no counterpart and are dropped. `t.step(name, fn)` is the same.
7. A test that needs `Deno.*` uses the table above, through the same runtime as the code.

How `ifc test` is fed (`tools/test.ts`, run by `bun run test`):

- **The requirements** are every line `- **FR-NNN** ...` of every `specs/*/spec.md` (also
  `FR-003a`), as `<spec folder> FR-NNN`, written to `test-results/requirements.txt` and given to
  `runTests` as `requirements`. The run fails while a requirement is neither proven nor reviewed
  (commons 0008-test-evidence), so the record says honestly what is not proven yet (all 694 at the
  start).
- **Reviewed requirements** (proven by review, not by a test: a VM install, a Windows boot machine,
  a document) are listed in `specs/<spec>/reviewed.tsv`: the requirement, a tab, the reason, one
  per line. They are joined into `test-results/reviewed.tsv`.
- **A mistyped id fails first**: every requirement a test file names (any string
  `"NNN-slug FR-NNN"`) and every reviewed one must be a requirement of a spec, or the run stops
  before it starts.
- **Runtimes**: `bun run test` runs Bun; `bun run test:ci` runs Bun and Node, with the TAP, JUnit,
  CTRF, SARIF, Markdown, HTML and OSCAL reports and the ledger `test-results/ledger.jsonl`, all CI
  artifacts.
