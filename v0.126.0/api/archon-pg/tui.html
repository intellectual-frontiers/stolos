tui

archon pg admin-tui (rainfrog) and archon pg observe-tui (pgcenter top): each finds the instance the way archon pg show does (an instance Archon keeps, any cluster here, or a service section) and starts the tool already connected. On this server: the socket and you as yourself (peer, no password). With --remote: the published name over TLS, verify-full against the system's roots. A password never goes on a command line (other users see those in ps): rainfrog asks for it; pgcenter gets it from ~/.pgpass or, asked here, in its own environment only.

Source: src/archon/pg/tui.ts

SYSTEM_ROOTSconst
const SYSTEM_ROOTS: "/etc/ssl/certs/ca-certificates.crt"

Ubuntu's bundle of trusted roots (what libpq's sslrootcert=system means on Linux).

TUISconst
const TUIS: { readonly rainfrog: { readonly what: "rainfrog (browse, query, edit)"; readonly command: "archon pg admin-tui"; }; readonly pgcenter: { readonly what: "pgcenter top (activity, statements, waits)"; readonly command: "archon pg observe-tui"; }; }

The terminal tools: what each is for, and the command that starts it.

Tuitype
type Tui = keyof typeof TUIS;

A terminal tool's name: rainfrog or pgcenter.

rainfrogArgsfunction
function rainfrogArgs(t: Target): string[]

rainfrog's --url (sqlx): the socket through the host parameter, or TLS verify-full.

pgcenterArgsfunction
function pgcenterArgs(t: Target): { args: string[]; env: Record<string, string>; }

pgcenter top (pgx): libpq's flags, and TLS through libpq's environment variables.

pgTuifunction
function pgTui(hostName: string, tool: "pgcenter" | "rainfrog", name: string, remote: boolean): Promise<number>

Start a terminal tool connected to NAME and return its exit code: 2 without a terminal or a password, 1 when the tool is missing or NAME is not found.
