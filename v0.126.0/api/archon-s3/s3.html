s3

041-s3: S3 object storage (RustFS), an opt-in container (spec 040), managed with archon fs s3. Identities are Linux accounts: every person on the server and every fleet service account has an S3 user of the same name, allowed the buckets named <name>-*. S3 signs requests with a secret the server keeps, so it cannot use the Linux password (Archon never puts a Linux password where it can be read back): each account's secret is generated on the server, and only that account (and root) can read it.

Source: src/archon/s3/s3.ts

Before the container first starts: its admin credentials, root only (never in /etc).

convergeS3function
function convergeS3(plan: { host: HostDef; fleet: FleetDef; users: UserDef[]; }, s: Sink): Promise<boolean>

Every identity has its S3 user, its secret (readable by that account only), and its policy; an identity Archon made that is not a person here or a fleet service account is disabled.

s3Statusfunction
function s3Status(hostName: string, json: boolean): Promise<number>

archon fs s3 status: on or off, since when, health, addresses, and (as root) its users.

s3Keyfunction
function s3Key(hostName: string, write: boolean, json: boolean, show?: boolean): Promise<number>

archon fs s3 key: your access key (your username) and secret, readable only by you. --write puts an AWS profile s3-<host> in ~/.aws/credentials and ~/.aws/config (0600), replacing only that profile.

s3Rotatefunction
function s3Rotate(hostName: string, o?: { readonly host?: HostDef | undefined; }): Promise<number>

archon fs s3 key --rotate: a new secret for the caller's S3 user, set in RustFS and written to their key file at once, so the old one stops working. Runs as root (sudo); the account is the person behind sudo. The secret is never printed, logged, or journaled; only that it changed.
