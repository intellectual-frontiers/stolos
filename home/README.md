# home/: the fleet's dotfiles (specs 011, 031)

The most general dotfile layer: every user on every host. More specific layers
live under `dotfiles/` (per host, per user, per user on one host); `archon
apply` composes them, in that order, into each user's chezmoi source under
`/var/lib/archon-dotfiles/<user>`. See the dotfiles guide (`archon docs dotfiles`, or src/archon/dotfiles/mod.ts) (`man
archon-dotfiles`). Per-user data
(`.archon.personas`, `.archon.features`, `.archon.fullName`, ...) is rendered
by `archon apply` into `~/.config/chezmoi/chezmoi.json` from the personas in
the host model, so `chezmoi apply` never prompts.

`.chezmoiignore` selects files by persona feature. Third-party dotfiles that
no model value feeds (tmux) are hand-authored (Article IV).

## The shell features: one line (spec 036)

`dot_bashrc.tmpl` and `dot_config/fish/config.fish.tmpl` hold Ubuntu's defaults
and one line that turns on Archon's shell features:

    eval "$(archon shell emit bash)"        # ~/.bashrc
    archon shell emit fish | source         # ~/.config/fish/config.fish
    eval "$(archon shell emit zsh)"         # ~/.zshrc (zsh is not installed by Archon)

`archon shell emit` prints code generated by `src/archon/shell/emit.ts`: the
modern `ls`, `ll`, `la`, `tree` (eza), `cat` (bat), `fd`; fzf's keys; zoxide's
`z`; delta for git; the terminal title (`<shell> in <user>@<host>`, as tmux's
`set-titles-string` says too); and the prompt. A layer without the line gets
none of it.

The prompt is plain (no icons; Archon's status in words) on a console
terminal, the physical console or a serial line, where no Nerd Font exists, and
Oh My Posh everywhere else, with `src/archon/shell/archon.omp.json` (installed
as `/usr/local/share/archon/shell/archon.omp.json`). `ARCHON_PROMPT=plain` or
`pretty` overrides that. The theme starts from `strategy-coach/workspaces-host`
`coach.omp.json`, with the azfunc, julia, and aws segments removed; where that
theme shows a language version on the right, this one shows Archon's status:
the last archon command's result, deferred disruptive changes, and whether
recorded state waits for `archon push` (`/var/lib/archon/status/prompt`). The
first segment shows the machine: the distro icon and the short host name.
