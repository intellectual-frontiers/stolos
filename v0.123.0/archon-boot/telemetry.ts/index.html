archon-boot/telemetry.ts

The boot server's own telemetry (spec 023, on IFC TypeScript since spec 096). The boot server's signals are IFC TypeScript's (runtime/otel), in-process: started once with {@link initBootTelemetry}, they are kept in a journal in the boot cache (OTLP JSON lines, OpenTelemetry's file format, rotated by size: 256 MB at most, and kept 30 days) and sent over OTLP/HTTP to otel-tui while it runs on this PC (localhost:4318, the pipeline's default; silent where nothing listens). Nothing else leaves the PC. There is no restart to turn telemetry on.

Spec 049: the boot server is also the fleet's default collector. Servers that find no other (fleet.telemetry, or otel.localdomain) send their telemetry to http://<boot PC>:<http port>/otlp, which IFC TypeScript's OTLP receiver decodes; it is kept a week (ephemeral) in daily files.

Each install is one trace, an archon.boot.install span (its host in host.name), with an archon.boot.step span per step (its name in archon.boot.step).

A handler for OTLP/HTTP with JSON bodies (gzip or not), on IFC TypeScript's OTLP receiver: each batch becomes one OTLP JSON line of a daily file in dir, pruned to keep; when otel-tui runs on this PC, the batch is also handed to it.
