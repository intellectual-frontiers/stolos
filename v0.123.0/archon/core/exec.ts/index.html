archon/core/exec.ts

The engine's way of running a program (spec 096-bun-runtime), on IFC TypeScript's proc. Archon calls Ubuntu's own binaries (apt-get, systemctl, nft, useradd, ...) directly, by their argument vector, never through a shell. Two things here are the engine's own, beyond proc.run:

  • a program that is not installed is an outcome, exit code 127 with "command not found", never an exception, so a check on a machine that lacks a tool reads like any other failure;
  • asUser runs it as another account through runuser(1), from that account's home folder (spec 009: never root's working directory, which the account usually cannot read).

stream gives a program's output line by line as it comes (apt's progress), splitting on carriage returns as well as line feeds. Everything else (which, isRoot, must, splitArgs) is IFC TypeScript's: proc.which, proc.isRoot, proc.must, and the kernel's splitArgs.

Example

import { run } from "./exec.ts";
const r = await run(["systemctl", "is-active", "ssh"]);
if (r.code === 127) console.log("no systemd here");

typeRunResult

export type RunResult = {
  /** The exit code (127 where the program is not installed). */
  readonly code: number;
  /** What it printed (empty with `inherit`). */
  readonly stdout: string;
  /** What it printed as errors (empty with `inherit`). */
  readonly stderr: string;
  /** Whether the exit code was 0. */
  readonly ok: boolean;
};

  /** Run it as this account through runuser(1) (needs root). */
