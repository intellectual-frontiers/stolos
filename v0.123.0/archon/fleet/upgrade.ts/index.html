archon/fleet/upgrade.ts

stolos fleet upgrade <tag> (spec 046-engine-instance, Articles 9, 12, 24; spec 096 FR-006): move a fleet repository to another released version of the engine, safely.

Why each step exists (the fleet-repository guide, ./mod.ts, says it at length):

  1. The tag must be a version tag, and only forward unless --downgrade: going back to an older engine is a decision, not an accident.
  2. package.json's dependency on the engine is moved to that release's tarball (https://github.com/intellectual-frontiers/stolos/releases/download/v<version>/intellectual-frontiers-stolos-<version>.tgz), and bun install records its integrity in bun.lock. The installed package must say it is that version: a typo, or an asset that is not that release, is refused and everything is put back. Hosts run bun install --frozen-lockfile: a tarball that differs from the lock is refused. That is what makes your signature cover the engine's bytes.
  3. Every fleet in the repository is validated with the new engine before anything is committed.
  4. The files are committed together and signed (git commit -S): hosts apply only a signed tip of main. Pushing it is the approval.
