archon/fedramp/package.ts

Spec 076: the FedRAMP 20x validation package for Class A or Class B, from the evidence Stolos already has. It is a Security Decision Record (SDR) in FedRAMP's own JSON format (SDR-CSX-KSI names the schema fedramp-security-decision-record-schema-2026-06-24.json): for each KSI the class asks for, the measures (Stolos's checks), their cycle, the automated validations with their results and observation times, and for a KSI Stolos cannot observe, why, so the provider writes its own.

flowchart LR
  facts["PcFacts: what this PC last observed"] --> ev["Evidence, with when each was observed"]
  ev --> map["KSI_MAP: checks per KSI"] --> ksi["Each KSI: status, tests, evidence, age"]
  rules["rules.auto.ts: Class A list, cadences (FedRAMP)"] --> ksi
  ksi --> sdr["Security Decision Record (FedRAMP JSON schema)"]

The classes differ as the rules say: Class A addresses the seven KSIs of FRC-CLA-MFR, automation is optional (FRC-CSX-VVK: MAY), machines are validated at least monthly (VDR-TFR-MVX: SHOULD), and the package is kept current every 3 months (CPO-CSX-CPM: SHOULD); Class B addresses every KSI (five marked "Optional" for it), with at least one automated method each (SHOULD), machines validated at least every 7 days (MUST), and the package kept current every month (MUST).

When each piece of evidence was observed comes from Evidence.observedAt when it has one (spec 073 may add it), else from the observation times the Stolos Console already knows (evidenceObservedAt): an adopted machine's or device's last probe, a cloud's last observation, a managed server's last pull or install, the repository's newest commit.
