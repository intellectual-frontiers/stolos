archon/estate/osquery.ts

Spec 093: the estate graph as osquery tables, through osquery's Automatic Table Construction (ATC). No extension and no new process: osquery reads estate.auto.sqlite.db itself, from a configuration generated here from the schema's declarations (ESTATE_SCHEMA), so every estate table and view is an osquery table named stolos_<name> with exactly its declared columns.

flowchart LR
  decl["ESTATE_SCHEMA (schema.ts)"] --> atc["estate.osquery.json: auto_table_construction"]
  git["observations in Git"] --> sql["estate.sql (canonical)"] --> db["estate.auto.sqlite.db (written to a temp file, then renamed)"]
  atc --> osq["osqueryi or osqueryd"]
  db --> osq
  osq --> q["select * from stolos_device"]

What ATC does (osquery's auto_constructed_tables.cpp): for each entry it opens the file at path read-only, runs query, and maps each result column to the declared column of the same name. Every column is TEXT in osquery (integers and booleans arrive as their decimal text; NULL as an empty value). ATC adds an implicit path column (the file it read) and treats a declared path as reserved, so a schema column named path is exposed as estate_path here; the estate's own names never change. platform is matched by substring, so darwin,linux,windows covers all three. A % in path is a wildcard; the estate's path is literal.

import { atcConfig } from "@stolos/archon/estate/osquery.ts";
const c = atcConfig("/home/alice/.local/state/stolos/estate/estate.auto.sqlite.db");
console.log(c.auto_table_construction.stolos_device.query);
