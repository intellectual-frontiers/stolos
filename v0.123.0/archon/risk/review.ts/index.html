archon/risk/review.ts

Spec 080: review through signed pull requests. A review changes a file in the fleet repository (a risk's next review date in risks.ts; new vendors in vendors.ts) on a branch of its own, in a commit signed with the reviewer's daily key, and opens a pull request with gh. The approval is the merge: a merge commit on the fleet's main branch signed by a fleet signer (git merge --no-ff -S, then stolos apply), checked like spec 072's evidence: git verify-commit against the fleet's signers.ts. A merge made on GitHub's website is signed by GitHub, not by a signer: it is approved by the next signed commit on main (stolos apply makes one), and {@link approvalOf} says which.

sequenceDiagram
  participant R as Reviewer (stolos risks review)
  participant G as Git (fleet repository)
  participant H as GitHub
  participant S as Signer
  R->>G: branch risks/review-<id>-<day> from origin/main
  R->>G: edit risks.ts, commit -S (daily key)
  R->>H: push, gh pr create
  S->>H: review the pull request
  S->>G: git merge --no-ff -S, stolos apply (push)
  G-->>R: approvalOf(risks.ts): the merge commit, signed by a fleet signer
