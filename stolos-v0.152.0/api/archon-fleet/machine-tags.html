machine-tags

Spec 112-machine-reported-tags FR-007, FR-008: the machine's side of tags. archon tag add | remove | list keep the tags a person on the machine says about it in the machine's own state database (archon.sql, the view archon_tags, which osquery reads), and each archon apply also writes the tags the fleet knows for the machine, worked out from the fleet repository the machine already holds. None of it changes the machine's configuration: it is what the machine says about itself, which the PC reads as claims and the fleet decides about (fromMachine in tags.ts).

Source: src/archon/fleet/machine-tags.ts

tagAddLocalfunction
function tagAddLocal(hostName: string, tags: string | readonly string[], o?: { custom?: boolean | undefined; }, dir?: string): Promise<number>

archon tag add <tag...> (spec 112-machine-reported-tags FR-007): say a tag about this machine, in its own table. Read with the tag grammar and its caps; a new value of a one-of dimension replaces this machine's own old one; a tag the fleet's tags.ts does not define is written, and said to be one the PC cannot accept.

tagRemoveLocalfunction
function tagRemoveLocal(hostName: string, tags: string | readonly string[], dir?: string): Promise<number>

archon tag remove <tag...> (spec 112-machine-reported-tags FR-007): take tags a person said off this machine's table (never the fleet's rows).

tagListLocalfunction
function tagListLocal(hostName: string, json: boolean, dir?: string): Promise<number>

archon tag list (spec 112-machine-reported-tags FR-007): this machine's own table, each row with its source.

fleetTagRowsfunction
function fleetTagRows(host: HostDef): Promise<{ rows: Pick<TagBody, "dimension" | "set_by" | "value">[]; error?: string | undefined; }>

The tags the fleet knows for this machine, from the fleet repository it already holds: a person's tags in its decisions.ts, then the rules and groups of tags.ts (spec 108-tags). Not what the machine says: the same resolution the PC does, without any claim.

refreshFleetTagsfunction
function refreshFleetTags(host: HostDef, dir?: string): Promise<{ changed: boolean; count: number; why?: string | undefined; }>

At each apply (spec 112-machine-reported-tags FR-008): write the tags the fleet knows for this machine with the source fleet, replacing the previous ones and leaving the machine's own alone. Never fails an apply: a fleet whose tags.ts does not load leaves the rows as they were.
